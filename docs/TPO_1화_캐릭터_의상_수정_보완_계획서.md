# TPO 1화 캐릭터·의상 아트 수정·보완 계획서

> 문서 상태: 수정 방향 합의안 v1.0  
> 작성일: 2026-07-26  
> 대상: 스토리 모드 1화 `구조대 입단 시험`  
> 현재 판정: **No-go — 현 아트의 부분 보정 및 다른 에피소드 확장 중단**  
> 작업 범위: 계획 수립만 수행. 코드 수정, 에셋 생성, 배포, Supabase 연계 없음  
> 작성 방식: 외부 인터뷰가 아닌 게임 아트 디렉터, 2D 테크니컬 아티스트,
> 아동 UX 연구자, 게임 기획자의 네 전문 역할에 의한 내부 패널 검토

## 1. 한눈에 보는 결론

현재 결과는 캐릭터 얼굴 한 장을 다시 그리거나 옷의 위치를 조금 옮기는
방식으로 해결하기 어렵다. 문제는 다음 세 가지가 동시에 발생한 것이다.

1. 캐릭터, 배경, 아이템 카드가 서로 다른 화풍과 원근으로 제작됐다.
2. 의상이 캐릭터의 몸에 맞춰 재단된 것이 아니라 독립 상품 이미지를
   확대·축소해 위에 올린 구조다.
3. 기존 계획에 있던 `골든 세트 승인 → 나머지 제작` 절차를 거치지 않고
   16개 품목을 먼저 완성해 구조적 오류가 전체 에셋에 반복됐다.

전문가 4인의 최종 합의는 다음과 같다.

- 현 이미지 버전은 비교 자료로 보존하되 더 이상 부분 수정하지 않는다.
- 다음 개발 재개 시점에는 새 아트가 승인될 때까지 초기 CSS 캐릭터를
  1화의 임시 표시안으로 되돌리는 것을 우선 검토한다.
- 최종 목표는 **초기 CSS 화면의 단순한 선·색·큰 실루엣을 계승한 귀여운
  의인화 동물 캐릭터**다.
- 1순위 가설은 작은 둥근귀와 짧은 꼬리를 가진 **3등신 아기 곰**이다.
- 동물로 바꾸는 것만으로 착용 문제가 해결되지는 않는다. 한 개의 마스터
  몸체, 고정 앵커, 신체 마스크, 앞·뒤 의상 레이어를 먼저 설계해야 한다.
- 동물 종과 스타일은 즉시 확정하지 않는다. 흑백 실루엣과 정지 합성본을
  비교한 뒤 승인한다.
- 정지 시안과 회색 테스트 의상이 통과하기 전에는 코드를 수정하거나
  16개 아이템을 다시 만들지 않는다.

## 2. 현재 화면 진단

### 2.1 관찰된 현상

| 현상 | 화면에서 보이는 문제 | 사용자 경험에 미치는 영향 |
|---|---|---|
| 캐릭터 주목성 부족 | 넓고 선명한 훈련장에 비해 캐릭터가 작고 아래에 놓임 | 옷입히기 대상보다 배경이 먼저 보임 |
| 화풍 불일치 | 배경은 회화풍, 캐릭터는 애니메이션 인물풍, 신발·옷은 상품 렌더풍 | 하나의 게임이 아니라 여러 그림을 합친 것처럼 보임 |
| 후드 접합 실패 | 목둘레, 어깨, 소매 축이 몸과 맞지 않음 | 입은 옷이 아니라 몸 위에 붙인 스티커처럼 보임 |
| 하의 접합 실패 | 허리, 골반, 무릎 위치가 몸과 정확히 연결되지 않음 | 바지가 몸의 형태를 감싸지 못함 |
| 신발 접합 실패 | 캐릭터는 정면인데 신발은 위에서 본 3/4 상품 시점이며 크기도 큼 | 발이 신발 안에 들어간 느낌이 사라짐 |
| 소품 접합 실패 | 반사 밴드처럼 팔·몸의 앞뒤를 오가는 물건을 한 장으로 처리 | 물건이 팔에 끼워지지 않고 공중에 떠 보임 |
| 카드와 착용물 차이 | 카드마다 선, 광원, 질감, 원근이 다름 | 카드에서 고른 물건과 입은 물건의 1:1 대응이 약해짐 |
| 성별·외모 구체성 | 현재 캐릭터가 특정 소년으로 강하게 읽힘 | 일부 아동에게 `내 캐릭터`보다 `남자아이 캐릭터`로 느껴질 수 있음 |
| 시선 연결 부족 | 선택 결과 목록이 캐릭터와 멀리 떨어져 있음 | 카드 선택과 캐릭터 변화의 관계를 즉시 파악하기 어려움 |

### 2.2 초기 CSS 화면이 상대적으로 나아 보이는 이유

초기 화면은 정교한 완성품은 아니었지만 다음 장점이 있었다.

- 캐릭터, 배경 효과, UI가 모두 굵은 선과 단순 도형으로 구성됐다.
- 제한된 네이비·노랑·크림 팔레트가 화면을 한 게임처럼 묶었다.
- 캐릭터가 크고 중앙에 있어 선택 결과가 즉시 보였다.
- 신체 구획이 단순해 상의, 하의, 신발의 경계가 분명했다.
- 과도한 질감이나 상품 원근이 없어 약간의 오차가 덜 눈에 띄었다.

따라서 초기안을 그대로 최종 사용한다는 의미가 아니라, **초기안의 통일성,
큰 실루엣, 제한된 채색을 새 아트의 기준선으로 복원**해야 한다.

## 3. 기존 계획이 결과를 막지 못한 이유

기존 문서에는 이미 다음 원칙이 있었다.

- AI 생성 결과를 기준 캐릭터와 최종 의상 레이어로 그대로 사용하지 않는다.
- 캐릭터와 의상은 하나의 벡터 원본과 같은 기준 캔버스를 사용한다.
- 기준 포즈와 앵커를 동결한다.
- 골든 세트를 실제 화면에 합성해 승인한 후 나머지 아이템을 제작한다.
- 카드 썸네일과 착용 레이어는 같은 마스터 원본에서 파생한다.
- 기존 CSS 화면보다 이해도와 재미가 개선되지 않으면 No-go로 판정한다.

현재 결과는 계획이 부족해서라기보다 **승인 절차가 실행되지 않은 것**에
가깝다.

| 계획상 안전장치 | 실제 문제 |
|---|---|
| AI는 무드보드·콘셉트에 제한 | 캐릭터와 품목별 독립 생성 결과가 최종 에셋이 됨 |
| 하나의 벡터 마스터 | 캐릭터와 의상이 서로 다른 원본과 비례로 제작됨 |
| 공통 앵커 오차 제한 | 캔버스 크기만 같고 목·어깨·손목·허리·발목 기준점이 공유되지 않음 |
| Gate A 골든 세트 승인 | 골든 세트 착용 승인 전에 16개 품목을 제작함 |
| 앞·뒤 레이어 분할 | 1화 품목을 대부분 한 장의 `wear-main`으로 단순화함 |
| 초기 CSS와 비교 | 비교 승인 없이 새 이미지 버전을 운영 화면에 적용함 |

기존 QA 문서의 판정 기준에 따르면 “이미지 버전이 기존 CSS 버전보다
이해도와 재미를 개선하지 못함”에 해당하므로 현재 상태는 명확한
**No-go**다.

## 4. 전문가 4인의 토의

### 4.1 참여 역할

| 역할 | 우선 질문 |
|---|---|
| 게임 아트 디렉터 | 어떤 캐릭터와 시각 문법이 한 게임처럼 느껴지는가? |
| 2D 테크니컬 아티스트 | 옷이 실제로 몸을 감싸 보이게 하려면 어떤 구조가 필요한가? |
| 아동 UX 연구자 | 성인 취향이 아니라 아동의 인지·동일시·학습으로 어떻게 판단하는가? |
| 게임 기획자 | 어느 범위까지 검증한 뒤 제작과 개발을 재개해야 손실을 줄일 수 있는가? |

### 4.2 1차 의견

**아트 디렉터**

- 핵심 실패는 이미지 해상도가 아니라 공통 시각 규칙의 부재다.
- 현재 사람 캐릭터는 화면의 편집 디자인과 맞지 않고 특정 인물로 읽힌다.
- 초기 CSS의 단순함을 계승한 의인화 동물이 브랜드성과 친근함 면에서
  가장 유망하다.

**테크니컬 아티스트**

- 캐릭터 종을 바꾸기 전에 독립 상품 이미지를 몸 위에 얹는 제작 방식을
  중단해야 한다.
- 동물도 앵커, 마스크, 관절 축, 앞·뒤 레이어가 없으면 똑같이 어색하다.
- 기술적으로 작은 귀와 거의 보이지 않는 꼬리를 가진 아기 곰이 모자,
  후드, 하의, 가방을 규격화하기 가장 쉽다.

**아동 UX 연구자**

- 동물 캐릭터가 성별 포용성과 친근함을 높일 가능성은 있으나 성인의
  `귀여움` 판단만으로 확정하면 안 된다.
- 초기 단순 캐릭터 개선안을 대조군으로 두고 동일한 옷, 크기, 배경으로
  비교해야 한다.
- 동물안이 더 귀여워도 옷 구분과 TPO 이유 설명이 나빠지면 채택하지 않는다.

**게임 기획자**

- 현재 에셋에 추가 비용을 쓰는 부분 보정은 중단한다.
- `종 선택 → 스타일 선택 → 착용 구조 → 골든 세트 → 정지 UI → 아동 검증`
  순서로 승인 관문을 다시 세운다.
- 정지 시안 단계에서는 코드를 건드리지 않고 실패 비용을 최소화한다.

### 4.3 주요 반론과 합의

| 쟁점 | 반론 | 최종 합의 |
|---|---|---|
| 동물이면 문제가 해결되는가? | 귀·꼬리·주둥이가 새 충돌을 만들 수 있음 | 작은 귀·짧은 꼬리의 한 종과 한 체형만 사용하고 마스터 리그를 먼저 만든다 |
| 사람 캐릭터가 학습 전이에 더 좋은가? | 실제 생활과 직접 연결된다는 장점이 있음 | 직립형 동물에게 사람과 같은 의상 부위·일상 상황을 명확히 부여하고 아동에게 전이 이해를 검증한다 |
| 초기 CSS로 완전히 돌아갈 것인가? | 안정적이지만 정식 게임의 매력과 브랜드성이 약함 | 초기 CSS는 임시 기준선과 표현 문법으로 보존하고, 최종은 그 문법을 고도화한 동물 캐릭터를 우선 검토한다 |
| 바로 16개 품목을 다시 만들 것인가? | 품목 수가 있어야 조합 검증이 가능하다는 의견 | 회색 테스트 4종과 완성 골든 세트만 먼저 검증하고 승인 후 8종, 마지막에 16종으로 확장한다 |

### 4.4 전문가 합의문

> 현재 결과를 부분 보정하는 방식은 권하지 않는다. 문제는 캐릭터 한 장이
> 아니라 캐릭터·의상·배경을 묶는 공통 규격이 지켜지지 않은 데 있다.
> 초기 CSS 화면의 장점인 큰 실루엣과 단순한 색·선을 되살리고, 사람 대신
> 둥근귀 아기 곰을 1순위 가설로 한 고정형 2D 의상 리그를 설계한다.
> 종 선택과 착용 구조는 정지 시안으로 먼저 검증하며, 승인 전에는 코딩과
> 16개 에셋 제작을 재개하지 않는다.

## 5. 방향 대안 비교

평가 점수는 1점이 가장 낮고 5점이 가장 높다. 점수는 실제 아동 테스트
결과가 아니라 네 전문 역할의 사전 위험 평가다.

| 대안 | 캐릭터 매력 | 착용 안정성 | TPO 명료성 | 확장성 | 일정 안전성 | 판단 |
|---|---:|---:|---:|---:|---:|---|
| A. 현재 사람 캐릭터 부분 수정 | 2 | 1 | 3 | 2 | 2 | 제외 |
| B. 사람 캐릭터를 마스터 리그부터 전면 재제작 | 3 | 3 | 5 | 4 | 2 | 예비안 |
| C. 초기 CSS 캐릭터 고도화 | 3 | 5 | 4 | 4 | 5 | 임시안·대조군 |
| D. 초기 CSS 문법 + 의인화 동물 고정 리그 | 5 | 4 | 4 | 4 | 3 | **목표안** |

## 6. 의인화 동물 후보

### 6.1 후보 비교

| 후보 | 장점 | 의상 충돌 위험 | 판단 |
|---|---|---|---|
| 둥근귀 아기 곰 | 작은 귀, 짧은 주둥이, 꼬리 노출이 거의 없음, 성별 중립적, 작은 화면에서 실루엣이 선명함 | 낮음 | **1순위** |
| 수달 | 친근하고 구조·물 테마와 연결 가능, 작은 귀 | 긴 몸통과 꼬리, 짧은 다리가 하의·신발을 제한 | 2순위 |
| 강아지 | 친숙하고 구조대 역할과 자연스럽게 연결 | 견종·늘어진 귀·주둥이가 모자와 후드에 충돌, 기존 유명 구조대 캐릭터와 유사해질 위험 | 3순위 |
| 토끼·고양이·여우·레서판다 | 강한 개성과 즉시 식별되는 실루엣 | 긴 귀, 뾰족한 귀, 큰 꼬리가 모자·후드·가방을 자주 침범 | 1차 후보 제외 |

### 6.2 종 선택 기준

1. 후드, 모자, 상의, 하의, 신발, 가방을 같은 몸 리그에 적용할 수 있는가?
2. 120px 높이에서도 얼굴과 손·발의 실루엣이 구분되는가?
3. 성별과 문화적 고정관념이 약한가?
4. 기본·성공·재도전 표정이 작은 눈·입 변화로 읽히는가?
5. 13개 TPO 상황 어디에 놓아도 특정 계절이나 직업에만 묶이지 않는가?
6. 귀·주둥이·꼬리가 착용 아이템의 기능 단서를 가리지 않는가?
7. 특정 유명 캐릭터나 프랜차이즈를 연상시키지 않는가?

### 6.3 아기 곰 기본 디자인 가설

- 키는 머리 약 3개 높이의 3등신
- 둥근 머리와 작은 반원형 귀
- 짧고 단순한 주둥이
- 화면에서 보이지 않거나 아주 짧은 꼬리
- 사람처럼 직립한 몸통과 분리된 어깨·골반
- 물건을 잡을 수 있는 엄지가 표현된 단순한 장갑형 앞발
- 발은 좌우 정면을 향하고 신발이 들어갈 충분한 면적 확보
- 기본 털색은 따뜻한 크림·연갈색 계열
- 속눈썹, 리본, 화장, 특정 성별 색상은 기본값에서 제외
- 사실적인 털, 발톱, 큰 유리구슬 눈, 과한 볼터치와 광택은 사용하지 않음

## 7. 새 아트 시스템의 필수 규격

### 7.1 마스터 캐릭터 원칙

- 몸체와 포즈는 하나만 제작한다.
- 준비·성공·재도전 상태는 눈, 눈썹, 입 등의 얼굴 레이어만 교체한다.
- 기본 몸에는 흰 티, 반바지, 양말 같은 외출복을 넣지 않는다.
- 털과 얇은 중립 속옷 또는 단순한 베이스 바디만 둔다.
- 모든 의상은 완성된 캐릭터 그림 위에서 직접 재단한다.
- 의상별 독립 상품 이미지를 확대·축소해 착용 레이어로 사용하는 것을 금지한다.

### 7.2 기준 캔버스와 앵커

기존 논리 캔버스 `1024 × 1536`은 유지할 수 있으나 다음 등록점을 실제
벡터 원본 또는 가이드 레이어로 공유해야 한다.

| 영역 | 필수 앵커 |
|---|---|
| 전역 | 원점, 바닥선, 전신 중심 |
| 머리 | 정수리, 목 중심, 좌우 귀 중심 |
| 상체 | 좌우 어깨, 좌우 팔꿈치, 좌우 손목 |
| 하체 | 좌우 골반, 좌우 무릎, 좌우 발목 |
| 발 | 좌우 발끝, 좌우 발바닥 |
| 동물 파츠 | 꼬리 시작점, 좌우 귀의 앞·뒤 경계 |

승인 오차:

- 앵커 드리프트: 원본 기준 4px 이하
- 손목과 커프의 틈·겹침: 4px 이하
- 발목 중심 오차: 5px 이하
- 준비·성공·재도전의 몸 실루엣 차이: 0px

### 7.3 레이어와 마스크

권장 전역 순서의 예:

```text
배경
→ 꼬리 뒤
→ 가방·우산 뒤
→ 의상 뒤판과 뒤쪽 소매
→ 캐릭터 몸
→ 하의 뒤
→ 신발
→ 하의 앞
→ 상의 몸판
→ 앞쪽 소매·커프
→ 손
→ 목 소품
→ 머리 소품 뒤
→ 귀
→ 머리 소품 앞
→ 손에 드는 소품 앞
→ 얼굴 표정
```

필수 가림 처리:

- 긴소매 상의: 팔은 가리되 손은 다시 앞에 표시
- 긴 상의: 하의 허리 부분을 필요한 만큼 가림
- 장화: 바짓단을 장화 안 또는 밖으로 처리하는 규칙 명시
- 모자·후드: 귀의 앞·뒤를 분리
- 가방·우산: 몸 뒤와 끈·손잡이 앞을 분리
- 하의·치마: 꼬리의 노출 또는 가림 규칙 명시

### 7.4 아이템 파일 구조

아이템마다 필요한 레이어만 선택하되 모든 파일은 같은 전체 캔버스와 원점을
사용한다.

| 슬롯 | 가능한 레이어 |
|---|---|
| 상의 | `top-back`, `top-main`, `sleeve-front-left/right`, `hood-front`, `body-mask` |
| 하의 | `bottom-back`, `bottom-main`, `bottom-front`, `tail-mask` |
| 신발 | `shoe-left`, `shoe-right`, `feet-mask`, `tongue-front` |
| 머리 소품 | `head-back`, `head-front`, `ear-mask` |
| 목·손·몸 소품 | `neck-back/front`, `body-back/front`, `hand-held` |

메타데이터 필수 항목:

- `itemId`
- `slot`
- `characterRigVersion`
- `requiredAnchors`
- `zGroups`
- `occlusionMasks`
- `compatibleBody`
- `boundingBox`
- `thumbnailPath`

### 7.5 카드 썸네일

- 카드용 그림은 착용 레이어와 별도의 생성 결과로 만들지 않는다.
- 동일한 마스터 의상 원본에서 카드용 정면 썸네일을 파생한다.
- 카드와 착용 결과는 색, 포켓, 지퍼, 밑창, 장식 위치가 같아야 한다.
- 모든 카드는 같은 정면 시점, 같은 광원, 같은 선 굵기, 같은 여백을 사용한다.
- 상품 사진 같은 3/4 위쪽 시점과 사실적 광택을 사용하지 않는다.

### 7.6 스타일 바이블 최소 기준

| 항목 | 기준 |
|---|---|
| 핵심 인상 | 명랑함, 안심, 명료함 |
| 외곽선 | 딥 네이비, 1024px 원본에서 5±1px |
| 내부선 | 3±1px |
| 채색 | 평면색 + 한 단계 그림자 |
| 광원 | 좌상단 35~45도 단일 광원 |
| 질감 | 학습에 필요한 방수·반사·보온 단서만 사용 |
| 팔레트 | 네이비·코럴·노랑·민트·크림 중심 |
| 금지 | 사진풍, 3D 상품광, 과도한 AI풍 광택, 무작위 주름 |
| 배경 | 캐릭터 주변의 채도·대비·세부 묘사를 한 단계 낮춤 |
| 캐릭터 크기 | 데스크톱 캐릭터 패널 높이의 약 58~65% |
| 바닥 | 캐릭터 발과 배경의 바닥 원근·기준선을 일치 |

## 8. 단계별 수정·보완 절차

### Gate 0 — 현 상태 동결과 기준선 보존

목적: 실패 원인을 잃지 않고 추가 손실을 막는다.

- 현 이미지 버전은 삭제하지 않고 비교·회귀 자료로만 보존
- 새 에셋 대량 생성 중단
- 초기 CSS 화면과 현재 화면을 같은 크기로 보존
- 현 화면의 목, 어깨, 손목, 허리, 발목, 소품 오류를 표시한 진단판 작성

승인 조건:

- 비교 기준 화면 2종과 문제 위치가 합의됨
- 현 버전을 부분 보정하지 않는다는 결정이 기록됨

### Gate 1 — 동물 종 실루엣 선택

개발 없이 정지 시안만 제작한다.

- 초기 CSS 개선 실루엣 1종
- 아기 곰 실루엣 1종
- 수달 실루엣 1종
- 강아지 실루엣 1종
- 각 안의 3등신 전신과 120px 축소본
- 의상, 배경, 표정 세부 묘사는 넣지 않음

평가 기준:

- 의상을 놓을 어깨·몸통·다리 면적
- 손·발 구분
- 귀·꼬리 충돌 위험
- 성별 중립성
- 작은 화면 판독성
- 특정 유명 캐릭터와의 비유사성

승인 결과: 한 종, 한 체형, 한 포즈만 선택한다.

### Gate 2 — 스타일 선택

선택한 종으로 두 표현안을 비교한다.

1. 초기 CSS에 가까운 초평면형
2. 평면색과 한 단계 그림자를 사용한 소프트 벡터형

제출물:

- 기본·성공·재도전 표정
- 제한된 팔레트
- 외곽선·내부선 확대 예시
- 실제 게임 크기 전신
- 저대비 훈련장 배경 위 정지 합성

승인 조건:

- 사용자에게 캐릭터가 호감으로 받아들여짐
- 120px에서도 얼굴과 손·발이 읽힘
- 배경보다 캐릭터가 먼저 보임
- 한 스타일과 한 팔레트만 선택됨

### Gate 3 — 회색 착용 구조 검증

완성 채색 전에 마스터 리그와 가림 규칙만 검증한다.

회색 테스트 품목:

- 긴소매 후드 상의
- 긴 바지
- 운동화 또는 장화
- 모자
- 반사 밴드
- 앞뒤가 있는 가방

검증 부위:

- 목과 후드
- 어깨와 소매산
- 손목과 커프
- 허리와 상·하의 경계
- 바짓단과 신발
- 귀와 모자
- 팔과 반사 밴드
- 몸과 가방끈

승인 조건:

- 기본 몸이나 속옷 누출 0건
- 손·귀·꼬리 관통 0건
- 떠 있는 소품 0건
- 신발과 바닥 분리 0건
- 세 표정에서 의상 위치 변화 0px

### Gate 4 — 완성 골든 세트

1화의 대표 착장을 같은 마스터 원본에서 완성한다.

- 구조대 재킷
- 활동 바지
- 운동화
- 구조대 모자
- 스트레스 품목인 반사 밴드와 가방 추가 비교
- 카드 썸네일과 착용 모습 나란히 표시
- 기본·성공·재도전 표정
- 데스크톱·태블릿·모바일 크기의 정지 화면

승인 전 금지:

- 나머지 아이템 제작
- React/CSS 연결
- 운영 사이트 교체

### Gate 5 — 게임성 확인용 8종

각 슬롯에서 정답 1개와 대표 오답 1개만 만든다.

| 슬롯 | 정답 예 | 대표 오답 예 |
|---|---|---|
| 상의 | 구조대 재킷 | 파티 셔츠 |
| 하의 | 활동 바지 | 긴 치마 |
| 신발 | 운동화 | 슬리퍼 |
| 소품 | 구조대 모자 또는 반사 밴드 | 장바구니 |

이 단계는 정답만 멋있게 만들지 않고 모든 품목이 매력적이되 현재 TPO에서
기능 차이가 읽히는지 확인한다.

### Gate 6 — 아동 정지 시안 검증

코드 없이 종이 카드나 동일 크기의 정지 화면으로 진행한다.

비교 조건:

- A안: 단순한 사람 캐릭터 개선안
- B안: 의인화 동물안
- C안: 초기 CSS 캐릭터 개선안

모든 안은 같은 배경, 캐릭터 크기, 옷, 표정, 정보량을 사용한다. 제시 순서는
참가자마다 바꾼다.

참가자:

- 빠른 형성평가: 초등 아동 최소 6명
- 세 안의 비교 결정을 위한 권장 평가: 초등 1~4학년 18명
- 저학년과 중학년이 한쪽으로 치우치지 않게 구성
- 보호자 동의, 불필요한 개인정보 수집 금지

### Gate 7 — 개발 및 16종 제작 승인

Gate 1~6이 통과한 뒤에만 다음을 승인한다.

- 1화 전체 16종 에셋 제작
- 실제 렌더러 연결
- 256개 조합 검수
- 초기 CSS 임시 표시안 교체
- 운영 사이트 배포

다른 에피소드와 Supabase는 계속 범위 밖으로 둔다.

## 9. 아동 검증 과업과 합격 기준

### 9.1 5초 인지 테스트

화면을 5초간 보여 준 뒤 가리고 묻는다.

- 어떤 캐릭터가 있었는가?
- 어디에 있었는가?
- 무엇을 하는 게임 같았는가?
- 무엇을 입고 있었는가?
- 어디에서 옷을 바꿀 것 같은가?

### 9.2 아이템과 착용 결과 연결

- 글자를 가린 의상 카드에서 운동화, 장화, 반사 밴드 등을 찾게 한다.
- 카드와 캐릭터가 입은 모습을 보고 같은 물건인지 묻는다.
- 몸의 어느 부위에 입는 물건인지 묻는다.
- “떠 있다”, “붙여 놓았다”, “몸을 가렸다” 같은 표현을 별도로 기록한다.

### 9.3 TPO 선택 이유

구조대 훈련, 비 오는 길, 운동회처럼 상황을 바꿔 제시하고 묻는다.

- 왜 이 아이템을 골랐는가?
- 다른 신발이나 옷보다 나은 이유는 무엇인가?
- 이 옷이 무엇을 편하거나 안전하게 만드는가?

설명 점수:

| 점수 | 기준 |
|---:|---|
| 0 | 이유 없음 또는 상황과 무관 |
| 1 | 색·예쁨·개인 취향만 언급 |
| 2 | 옷의 기능을 언급 |
| 3 | 상황과 기능을 인과적으로 연결 |

### 9.4 동일시와 재방문 의향

- 내가 이 캐릭터가 되어도 자연스러운가?
- 이 캐릭터와 같이 놀고 싶은가?
- 누구를 위한 게임처럼 보이는가?
- 어느 캐릭터로 한 번 더 하고 싶은가?
- 가장 마음에 든 이유와 불편한 이유는 무엇인가?

### 9.5 합격 기준

| 지표 | 합격 기준 |
|---|---:|
| 5초 안에 옷입히기 게임으로 인지 | 80% 이상 |
| 글자 없이 주요 의상 구분 | 85% 이상 |
| 카드와 착용 결과를 같은 물건으로 인지 | 90% 이상 |
| 올바른 신체 부위에 자연스럽게 입었다고 응답 | 90% 이상 |
| 떠 있음·붙여 놓음·신체 가림 지적 | 10% 이하 |
| 상황에 맞는 코디 선택 | 75% 이상 |
| 기능과 상황을 연결한 2점 이상 설명 | 70% 이상 |
| 처음 보지 않은 상황으로 전이 성공 | 70% 이상 |
| 다시 하고 싶다는 긍정 응답 | 75% 이상 |
| 내가 이 캐릭터여도 자연스럽다는 응답 | 80% 이상 |

동물안 채택 규칙:

- 초기 개선안보다 귀여움 또는 재도전 의향이 10%포인트 이상 높음
- 주요 의상 구분과 TPO 설명 능력은 초기안보다 5%포인트 이상 낮지 않음
- 착용 자연스러움 90% 이상

결과가 비슷하면 제작 위험이 낮고 사용자가 선호했던 초기 단순 캐릭터
개선안을 선택한다.

## 10. 기술 검수 매트릭스

### 10.1 최소 위험 조합

| 조합 | 확인할 문제 |
|---|---|
| 후드 + 모자 | 후드, 귀, 모자의 앞뒤 |
| 긴소매 + 반사 밴드 | 팔과 밴드의 관통·부유 |
| 긴소매 + 가방 | 소매, 손, 가방끈 |
| 긴바지 + 운동화 | 바짓단과 신발 혀 |
| 긴바지 + 장화 | 바지의 장화 안·밖 규칙 |
| 긴 치마 + 꼬리 | 꼬리 가림과 치마 실루엣 |
| 후드 + 목 호루라기 | 목, 끈, 후드의 깊이 |
| 모자 + 성공·재도전 표정 | 얼굴만 바뀌고 모자 위치가 유지되는지 |

핵심 위험 조합은 최소 16개로 확장해 100%와 200% 크기에서 수동 검수한다.
전체 16종 제작 후에는 256개 조합을 접촉 시트로 전수 확인한다.

### 10.2 즉시 실패 기준

- 기본 몸 또는 속옷이 목, 겨드랑이, 허리, 바짓단에서 보임
- 손, 귀, 꼬리가 사라지거나 옷을 뚫음
- 표정에 따라 옷의 위치가 움직임
- 신발 바닥선이 발 또는 지면과 분리됨
- 사진풍·3D풍 아이템이 벡터 캐릭터와 혼용됨
- 카드와 착용물의 핵심 형태가 서로 다름
- 아이템별 전용 CSS 위치 보정이 필요함

### 10.3 승인 기준

- 16개 위험 조합의 치명적 관통·누출 0건
- 경미한 시각 결함 2건 이하
- 200% 확대 시 검정·초록 매트와 반투명 테두리 0건
- 전문가 내부 평가 4명 중 3명 이상이 스타일 일관성, 귀여움, 착용
  자연스러움에서 각각 4/5 이상
- 아동의 80% 이상이 붙인 그림이 아니라 입은 옷으로 인식

## 11. 화면 구성 보완 원칙

캐릭터만 바꾸고 현재 레이아웃을 유지하면 배경 우세 문제가 남는다.

- 캐릭터 높이는 패널의 58~65%를 목표로 한다.
- 발은 배경의 같은 바닥선에 고정한다.
- 캐릭터 뒤 영역의 배경 채도, 대비, 디테일을 낮춘다.
- 훈련장 단서는 가장자리와 중경에 두고 캐릭터 뒤에는 큰 사물을 두지 않는다.
- 선택 결과 요약은 캐릭터와 가까운 하단 또는 카드 영역에 통합한다.
- 카드의 선택과 캐릭터 변화 사이의 시선 이동 거리를 줄인다.
- 카드 4개만 표시되는 탭에서 과도한 빈 공간이 생기지 않도록 카드와
  설명의 크기, 캐릭터 패널과의 비율을 정지 시안에서 함께 검토한다.

## 12. 제작 일정안

일정은 승인이 한 번에 통과된다는 가정이며, 미통과 시 해당 Gate만 반복한다.

| 단계 | 예상 기간 | 산출물 | 개발 여부 |
|---|---:|---|:---:|
| Gate 0 | 0.5일 | 현재·초기 비교판, 문제 표시판 | 없음 |
| Gate 1 | 1일 | 4개 흑백 실루엣 | 없음 |
| Gate 2 | 1~1.5일 | 2개 스타일·3표정·팔레트 | 없음 |
| Gate 3 | 1.5~2일 | 마스터 리그, 회색 테스트 6종 | 없음 |
| Gate 4 | 2일 | 완성 골든 세트와 정지 화면 | 없음 |
| Gate 5 | 1.5~2일 | 정답·오답 8종 정지 시안 | 없음 |
| Gate 6 | 1~3일 | 아동 검증과 결정표 | 없음 |
| Gate 7 | 별도 산정 | 16종 제작·개발·검수·배포 | 승인 후 |

개발 재개 전 계획 단계는 약 8~11영업일이다. 사용자 승인과 아동 모집
기간은 별도다.

## 13. 역할과 승인 책임

| 역할 | 책임 | 승인 대상 |
|---|---|---|
| 제품 책임자 | 범위, 일정, 중단·재개 판단 | 각 Gate의 진행 여부 |
| 아트 디렉터 | 캐릭터, 팔레트, 선, 배경 대비 | 종·스타일·골든 세트 |
| 테크니컬 아티스트 | 리그, 앵커, 마스크, 레이어 | 회색 착용 구조와 조합 QA |
| 아동 UX 연구자 | 비교 조건, 질문, 행동 기록 | 아동 검증 결과 |
| 개발자 | 승인된 규격의 렌더러 연결 | Gate 7 이후 빌드 |

한 담당자가 제작과 최종 승인을 동시에 하지 않는다. 최소한 아트와 착용
구조는 서로 다른 역할이 교차 검수한다.

## 14. 금지할 접근

- 현재 사람 캐릭터의 얼굴만 다시 생성하기
- 독립 상품 이미지를 빈 캔버스에 배치해 착용 레이어로 사용하기
- 카드 썸네일과 착용 레이어를 서로 다른 생성 결과로 만들기
- 종·포즈 승인 전에 16개 아이템을 다시 생성하기
- 목, 어깨, 허리, 신발 문제를 아이템별 CSS 좌표로 보정하기
- 표정마다 몸이 다른 완성 캐릭터 이미지를 사용하기
- 모자, 가방, 우산, 반사 밴드를 모두 같은 단일 소품 레이어로 처리하기
- 배경을 캐릭터보다 더 선명하고 복잡하게 만들기
- 동물을 선택했다는 이유만으로 귀여움과 학습 효과를 가정하기
- 아동 검증 전에 다른 에피소드로 같은 아트 시스템을 확장하기

## 15. 위험과 대응

## 16. 최종 승인 체크리스트

### 캐릭터

- [ ] 한 종, 한 체형, 한 포즈가 승인됐다.
- [ ] 초기 CSS보다 호감과 동일시가 낮지 않다.
- [ ] 120px에서 얼굴, 손, 발이 구분된다.
- [ ] 성별 고정 표현과 유명 캐릭터 유사성이 없다.

### 착용 구조

- [ ] 마스터 몸체와 앵커가 동결됐다.
- [ ] 세 표정에서 몸 실루엣이 동일하다.
- [ ] 회색 테스트 6종이 관통·누출 없이 맞는다.
- [ ] 모자·후드·가방·반사 밴드의 앞뒤가 자연스럽다.
- [ ] 카드와 착용물은 같은 마스터 원본에서 파생된다.

### 화면

- [ ] 캐릭터가 배경보다 먼저 보인다.
- [ ] 캐릭터 높이가 패널의 58~65%다.
- [ ] 카드 선택과 캐릭터 변화의 시선 연결이 짧다.
- [ ] 데스크톱·태블릿·모바일 정지 화면이 모두 승인됐다.

### 아동 검증

- [ ] 옷입히기 게임 인지율이 80% 이상이다.
- [ ] 주요 의상 식별률이 85% 이상이다.
- [ ] 카드와 착용물 동일 인지가 90% 이상이다.
- [ ] 착용 자연스러움이 90% 이상이다.
- [ ] TPO 기능 설명과 재도전 의향 기준을 충족했다.

### 개발 재개

- [ ] Gate 1~6의 결과와 승인자가 기록됐다.
- [ ] 미해결 P0·P1 문제가 없다.
- [ ] 1화 16종 제작과 코드 연결 범위만 승인됐다.
- [ ] 다른 에피소드와 Supabase가 계속 제외 범위로 유지됐다.

## 17. 다음 행동 제안

이 문서가 승인될 경우 다음 작업은 개발이 아니다.

1. 현재 화면과 초기 CSS 화면을 같은 크기로 놓은 비교판을 만든다.
2. 초기 CSS 개선형, 아기 곰, 수달, 강아지의 흑백 실루엣 4개만 만든다.
3. 실제 게임 표시 크기인 120px 축소본을 함께 비교한다.
4. 한 종과 한 체형이 승인되면 두 가지 평면 스타일 시안으로 넘어간다.
5. 스타일 승인 후에만 회색 착용 구조를 설계한다.

그 전에는 코드, 운영 사이트, 기존 에셋, Supabase를 변경하지 않는다.
