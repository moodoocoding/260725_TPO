# TPO 아트 버티컬 슬라이스 QA 체크리스트

> 대상: 스토리 모드 에피소드 1 `비 오는 저녁, 마트 심부름`
> 범위: 캐릭터 1종, 의상·신발·소품 16종, 256개 조합
> 제외: 로그인, Supabase, 배틀, 에피소드 2
> 판정: `[ ]` 미검증 · `[x]` 통과 · `[!]` 결함

## 1. 자동 검증

실행:

```powershell
node scripts/validate-art-assets.mjs
node --test tests/art-manifest.test.mjs
```

- [ ] 게임 데이터의 아이템 ID가 정확히 16개다.
- [ ] `art-manifest.json`의 아이템 ID가 게임 데이터와 모두 일치한다.
- [ ] `public/art/v1/items` 디렉터리 이름이 게임 데이터 ID와 모두 일치한다.
- [ ] 16개 아이템 모두 `thumb.webp`가 있다.
- [ ] 썸네일은 WebP, 512×384px, 파일당 35KB 이하다.
- [ ] 모든 착용 WebP가 1024×1536 투명 캔버스다.
- [ ] 단일 착용 아이템에 `wear-main.webp` 또는 지정된 `wear-front.webp`가 있다.
- [ ] 노란 우비에 `wear-back.webp`와 `wear-main.webp`가 있다.
- [ ] 투명·검정 우산에 각각 `wear-back.webp`와 `wear-front.webp`가 있다.
- [ ] 장바구니에 `wear-back.webp`와 `wear-front.webp`가 있다.
- [ ] 착용 WebP는 파일당 100KB 이하, 평균 60KB 이하다.
- [ ] 배경은 WebP, 1920×1440px, 300KB 이하다.
- [ ] 캐릭터와 표정 파일 합계가 300KB 이하다.
- [ ] `public/art/v1` 전체가 2MB 이하다.
- [ ] 런타임 아트 디렉터리에 SVG와 검수용 PNG가 없다.

자동 검증 실패 시 아동 테스트 후보로 승인하지 않는다.

## 2. 기본 기능 회귀

- [ ] 옷장 진입, 문자 확인, 타이머 시작, 코디 제출 흐름이 기존과 같다.
- [ ] 각 탭에 정확히 4개 아이템이 표시된다.
- [ ] 아이템 선택 직후 해당 그림이 캐릭터에 반영된다.
- [ ] 같은 슬롯의 다른 아이템을 고르면 이전 아이템이 교체된다.
- [ ] 선택 해제와 `모두 벗기`가 정상 동작한다.
- [ ] 선택 상태가 색 외에도 체크, 테두리, `입는 중` 문구로 표시된다.
- [ ] 제출 후 선택한 4개 아이템이 결과 화면에 동일하게 표시된다.
- [ ] 추천·비추천 조합의 점수와 안전 상한 규칙이 기존과 같다.
- [ ] 다시 코디하기 후 선택 상태와 타이머가 의도한 상태로 초기화된다.
- [ ] 최고점과 진행도가 새로고침 후에도 `localStorage`에서 유지된다.
- [ ] 이미지 로딩 실패 시 CSS 캐릭터로 전체 폴백된다.
- [ ] 이미지 캐릭터와 CSS 의상이 한 화면에서 섞이지 않는다.

## 3. 레이어와 256개 조합

상의 4 × 하의 4 × 신발 4 × 소품 4, 총 256개를 자동 캡처 또는 조합
그리드로 확인한다.

- [ ] 256개 조합이 모두 렌더링되고 빈 이미지가 없다.
- [ ] 캐릭터의 얼굴, 손, 발이 의도하지 않게 가려지지 않는다.
- [ ] 상의와 하의 사이에 몸이 비거나 배경이 보이지 않는다.
- [ ] 긴 치마와 모든 신발 조합에서 신발의 앞뒤가 자연스럽다.
- [ ] 반바지와 장화 조합에서 다리와 장화가 겹치지 않는다.
- [ ] 우비 후드는 머리 뒤, 우비 본체는 몸 앞에 표시된다.
- [ ] 우산 캐노피는 캐릭터 뒤, 손잡이는 손과 몸 앞에 표시된다.
- [ ] 장바구니 본체는 몸 뒤, 끈은 어깨와 몸 앞에 표시된다.
- [ ] 반사 밴드는 선택한 상의 위에서 보인다.
- [ ] 투명 우산을 통해 얼굴과 앞쪽 실루엣이 구분된다.
- [ ] 검정 우산이 어두운 배경과 완전히 합쳐지지 않는다.
- [ ] 빗줄기 뒤·앞 레이어가 캐릭터와 옷을 부자연스럽게 가리지 않는다.
- [ ] 추천 조합과 최저점 조합을 별도로 확대해 확인했다.

결함은 다음과 같이 기록한다.

| 등급 | 정의 | 예시 |
|---|---|---|
| 치명 | 진행 불가 또는 안전 의미 왜곡 | 아이템 미표시, 우산 앞뒤 반전 |
| 주요 | 과업은 가능하지만 식별·조작에 큰 영향 | 장화가 바지 뒤로 사라짐 |
| 보통 | 일부 조합에서 품질 저하 | 소매 경계가 3~5px 어긋남 |
| 경미 | 의미와 조작에 영향 없는 미세한 시각 문제 | 작은 선 두께 차이 |

## 4. 모바일·태블릿·데스크톱

필수 화면:

- 모바일: 360×800
- 소형 모바일: 320×568
- 태블릿: 768×1024
- 데스크톱: 1440×900

각 화면에서 다음을 확인한다.

- [ ] 캐릭터가 잘리거나 옷장 영역을 침범하지 않는다.
- [ ] 문자와 TPO 단서가 확대 없이 읽힌다.
- [ ] 카드 이미지 비율이 찌그러지지 않는다.
- [ ] 모든 버튼과 아이템 카드의 터치 영역이 44×44px 이상이다.
- [ ] 가로 스크롤이 생기지 않는다.
- [ ] 하단 출발 버튼이 브라우저 UI에 가려지지 않는다.
- [ ] 화면 회전 후 선택 상태와 착장이 유지된다.
- [ ] 200% 확대에서도 품목명, 설명, 선택 상태가 잘리지 않는다.
- [ ] 느린 연결에서 이미지 공간이 먼저 확보되어 화면이 밀리지 않는다.
- [ ] 캐시된 아이템은 선택 후 150ms 이내, 첫 선택은 500ms 이내 반영된다.

## 5. 키보드

마우스를 사용하지 않고 다음 흐름을 완료한다.

- [ ] `Tab` 순서가 문자 → 옷장 탭 → 아이템 → 출발 버튼 순으로 자연스럽다.
- [ ] 현재 포커스가 모든 배경에서 명확하게 보인다.
- [ ] `Enter` 또는 `Space`로 탭과 아이템을 선택할 수 있다.
- [ ] 방향키를 지원하는 탭 패턴이라면 선택과 포커스 규칙이 일관된다.
- [ ] 선택한 아이템을 키보드로 다시 해제하거나 교체할 수 있다.
- [ ] `모두 벗기`, 제출, 다시 코디하기를 키보드로 실행할 수 있다.
- [ ] 모달 또는 결과 화면에서 포커스가 사라지거나 뒤로 빠지지 않는다.
- [ ] 키보드만으로 전체 코디 과업을 완료할 수 있다.

## 6. 스크린리더

NVDA와 Chrome 또는 VoiceOver와 Safari 중 최소 한 조합으로 확인한다.

- [ ] 장식용 개별 레이어는 스크린리더에서 숨겨진다.
- [ ] 캐릭터 전체는 현재 착장을 한 문장으로 읽는다.
- [ ] 아이템 카드에서 품목명, 기능 설명, 선택 상태를 순서대로 읽는다.
- [ ] `aria-pressed`가 실제 선택 상태와 일치한다.
- [ ] 선택 변경 시 `aria-live`가 짧고 중복 없이 알려준다.
- [ ] 탭의 역할, 선택 상태, 연결된 패널이 올바르게 전달된다.
- [ ] 타이머가 매초 읽혀 방해하지 않고 필요한 경고만 전달된다.
- [ ] 이미지가 실패해 CSS 폴백으로 바뀌어도 같은 설명을 제공한다.
- [ ] 색을 보지 않아도 선택 상태와 결과 피드백을 이해할 수 있다.

## 7. 아동 사용성 테스트

권장 대상은 초등 아동 5~8명이다. 보호자 동의를 받고 참가자 번호만
기록한다. 진행자는 정답을 알려주거나 특정 아이템을 강조하지 않는다.
현장 진행 대본과 기록지는 [`docs/usability`](usability/README.md)의 테스트
패키지를 사용한다.

### 과업 A: 글자 없이 아이템 구분

1. 이름과 설명을 가린 아이템 그림을 보여준다.
2. “이건 무엇처럼 보여?”, “언제 사용할 것 같아?”라고 묻는다.
3. 우비·일반 외투, 장화·운동화, 투명·검정 우산의 차이를 묻는다.

- [ ] 전체 그림 식별률이 85% 이상이다.
- [ ] 우비·장화·투명 우산·반사 밴드 식별률이 각각 90% 이상이다.
- [ ] 아이가 색뿐 아니라 후드, 밑창, 투명도, 반사광 같은 형태 단서를 말한다.

### 과업 B: 문자에서 TPO 찾기

1. 에피소드 문자를 읽거나 듣게 한다.
2. “언제야?”, “어디에 가?”, “무엇을 하려고 해?”라고 묻는다.
3. “무엇을 조심해야 할까?”라고 묻는다.

- [ ] 아동의 80% 이상이 시간·장소·상황 중 2개 이상을 설명한다.

### 과업 C: 도움 없이 첫 코디

“이 상황에 맞게 옷을 골라 줘”라고만 안내한다.

- [ ] 도움 없는 완료율이 90% 이상이다.
- [ ] 선택·해제·교체 성공률이 85% 이상이다.
- [ ] 선택 후 캐릭터 변화 인지율이 90% 이상이다.
- [ ] 반복적으로 잘못 누르거나 찾지 못하는 UI가 없다.

### 과업 D: 이유 설명과 전이

1. “왜 이 우산과 신발을 골랐어?”라고 묻는다.
2. “점수 말고 문자 속 상황으로 설명해 줄 수 있어?”라고 묻는다.
3. “비가 그치고 밝은 낮이라면 무엇을 바꾸고 싶어?”라고 묻는다.

- [ ] 아동의 80% 이상이 아이템 기능과 상황을 연결해 설명한다.
- [ ] 아동의 75% 이상이 바뀐 상황에 맞는 아이템을 합리적으로 교체한다.
- [ ] 아이가 오답 아이템을 항상 나쁜 옷이라고 일반화하지 않는다.

### 과업 E: 재미와 재플레이

“가장 재미있었던 순간은 언제였어?”, “다른 코디로 다시 해보고 싶어?”라고
묻는다. “재미있었지?”처럼 답을 유도하지 않는다.

- [ ] 재미 평가의 5점 척도 중앙값이 4 이상이다.
- [ ] 아동의 75% 이상이 다시 코디하거나 다음 이야기를 원한다.
- [ ] 점수 확인보다 아이템을 교체하고 캐릭터를 비교하는 행동이 관찰된다.

## 8. Go / Revise / No-go

### Go

- [ ] 모든 P0 자동·기능 검증을 통과했다.
- [ ] 치명적 레이어·조작 오류가 0건이다.
- [ ] 주요 오류가 모두 수정되고 재검증됐다.
- [ ] 핵심 아이템 식별과 TPO 이유 설명 목표를 충족했다.
- [ ] 재플레이 의향이 75% 이상이다.
- [ ] 시험용 신규 아이템을 그림 제작 제외 30분 안에 등록했다.
- [ ] 신규 아이템 등록을 위해 렌더러, 카드, 전역 CSS를 수정하지 않았다.

### Revise

- [ ] 특정 2~3개 아이템에만 혼동이 집중된다.
- [ ] 목표 1~2개가 기준보다 10%포인트 이내로 부족하다.
- [ ] 캐릭터 변화는 보이지만 선택·해제가 불명확하다.
- [ ] 레이어 구조는 동작하지만 정렬·용량·제작 규칙 개선이 필요하다.

Revise이면 1~2주 수정 후 실패한 핵심 과업만 다시 검증한다.

### No-go

- [ ] 핵심 아이템 다수가 그림만으로 구분되지 않는다.
- [ ] 캐릭터 변화 인지율이 70% 미만이다.
- [ ] 그림이 안전 관련 오개념을 반복적으로 유발한다.
- [ ] 새 아이템마다 전용 React 조건문이나 CSS가 필요하다.
- [ ] 아트 적용본이 기존 CSS 버전보다 이해도와 재미를 개선하지 못한다.
