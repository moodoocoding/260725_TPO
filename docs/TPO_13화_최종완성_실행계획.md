# TPO 스타일 구조대 13화 최종 완성 실행계획

## 1. 완성 목표

스토리 모드의 프롤로그와 네 챕터, 총 13개 에피소드를 하나의 이어지는 이야기로 완성한다. 각 에피소드에서는 문자를 보낸 친구가 직접 옷을 입고, 같은 공통 동물 리그 위에 상황별 의상을 자연스럽게 겹쳐 입는다.

최종 완성의 기준은 다음과 같다.

- 13화 전체에 도입 이야기, 문자 요청, 코디, 결과 이야기, 다음 화 연결이 있다.
- 1·5화의 하루를 제외한 각 화의 착용 캐릭터가 모두 다르다.
- 캐릭터와 의상은 `1024 × 1536` 공통 리그를 사용한다.
- 상·하의 허리선, 발목과 신발, 얼굴 소품이 어긋나지 않는다.
- 각 슬롯에는 항상 4개의 선택지가 보이며 256개 조합을 만들 수 있다.
- 첫 번째 카드만 반복해서 고르는 위치 전략으로 전체를 통과할 수 없다.
- 실패해도 선택한 옷이 유지되고 즉시 다시 도전할 수 있다.
- 데스크톱과 `390 × 844` 모바일에서 주요 조작이 화면 안에 들어온다.
- Supabase 없이 모든 핵심 게임 흐름이 동작한다.

## 3. 제작 단계와 합격 기준

### 단계 A — 이야기 버티컬 슬라이스

1. 프롤로그와 네 챕터의 시작·종료 장면을 연결한다.
2. 13화 각각에 사건의 원인, 요청, 성공 후일담, 재도전 문장, 다음 화 예고를 연결한다.
3. 성공 뒤 TPO 이유 설명과 새 상황 전이 문제를 배치한다.

합격 기준:

- 모든 화면 문장이 초등학생이 한 번에 읽을 수 있는 길이다.
- 장례식은 문화와 가족의 안내를 존중한다.
- 최종화는 실제 재난이 아니라 졸업용 가상훈련임을 분명히 한다.
- 챕터 마지막에는 에피소드 예고와 챕터 예고가 중복되지 않는다.

### 단계 B — 공통 동물 캐릭터 리그

1. 1화 수달의 목 아래 몸 좌표를 13화 공통 기준으로 사용한다.
2. 요청자별 머리, 얼굴 무늬, 털색, 표정 세 종류를 제작한다.
3. 5화의 하루는 1화와 같은 캐릭터 파일을 재사용한다.

합격 기준:

- 허리 중심 `x=526`, `y=858±4`
- 맨발 바닥 `y=1278`
- 신발 밑창 `y=1308±4`
- 캐릭터별 런타임 이동·확대·축소 보정 0건
- 요청자 이름과 실제 표시 캐릭터 불일치 0건

### 단계 C — 13화 의상 시스템

1. 전체 카탈로그 의상을 공통 동물 리그용 착용 레이어로 생성한다.
2. 뒤 레이어, 본체, 하의, 신발, 상의, 소품, 앞 레이어, 얼굴 순서를 고정한다.
3. 카드 썸네일과 실제 착용 모습이 같은 형태를 갖도록 만든다.

합격 기준:

- 각 화에서 상의·하의·신발·소품이 각 4개씩 보인다.
- 모든 의상 파일과 썸네일이 존재한다.
- 상·하의 허리 틈, 신발 부유, 소품 관통 0건
- 13화 대표 코디 접촉 시트의 정적 검증 통과

### 단계 D — 게임 흐름과 공정성

1. 첫 의상 선택부터 제한 시간을 시작한다.
2. 실패 재도전에서는 현재 선택을 보존한다.
3. 회차와 슬롯에 따라 카드 시작 위치를 바꾼다.
4. 점수·별·진행 상태의 기존 저장 기록을 새 형식으로 안전하게 옮긴다.

합격 기준:

- 13화 × 256개 조합에서 만점·통과·실패 조합이 모두 존재한다.
- 첫 카드 반복 전략의 통과 수가 전체 13화 중 4화 이하이다.
- 미완성 코디 제출, 시간 종료, 실패, 재도전, 성공 흐름이 모두 막힘없이 이어진다.

### 단계 E — 대리 플레이와 출시

1. 빠른 선택형, 느린 읽기형, 탐색형, 재도전자 관점으로 전편을 시뮬레이션한다.
2. 데스크톱과 모바일에서 프롤로그, 각 챕터 대표 화, 피날레를 실제 화면으로 확인한다.
3. 코드 검사, 스토리 검사, 아트 검사, 빌드 검사를 모두 실행한다.
4. 검증한 동일 소스 상태를 GitHub `main`과 운영 사이트에 배포한다.

합격 기준:

- 자동 검사와 프로덕션 빌드 모두 성공
- 브라우저 콘솔 오류 0건
- 모바일 가로 넘침과 주요 버튼 잘림 0건
- 운영 URL에서 최신 캐릭터, 컷신, 의상 에셋 확인

## 4. 범위에서 미루는 항목

로그인 창은 유지하지만 실제 로그인과 Supabase 연동은 이번 완성 범위에 넣지 않는다. 데이터베이스가 없어도 13화 전체 플레이와 브라우저 내 진행 저장이 가능해야 한다. Supabase는 향후 계정 간 기록 동기화나 배틀 기록이 필요할 때 마지막 단계에서 연결한다.
