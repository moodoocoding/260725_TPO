# Gate 8 어린이 플레이테스트 실행계획서

- 대상 빌드: 1화 `구조대 입단 시험`
- 테스트 주소: <https://tpo-style-rescue-270725.panthea.chatgpt.site>
- 권장 참여자: 초등학생 3~5명
- 권장 시간: 1명당 15~20분
- 테스트 목적: 기능 검사가 아니라 어린이가 설명 없이 게임을 이해하고 즐기는지 확인
- 데이터 원칙: 이름 대신 `P01` 같은 참여자 코드만 사용하며, 로그인·Supabase·개인정보 수집은 사용하지 않음

## 1. 이번 Gate에서 답해야 할 질문

1. 어린이가 첫 화면에서 도움 없이 게임을 시작할 수 있는가?
2. 문자에서 시간·장소·상황 단서를 구분할 수 있는가?
3. 글을 모두 읽기 전에 의상 그림만 보고 물건의 종류와 기능을 구분할 수 있는가?
4. 의상을 선택할 때 캐릭터가 변하는 모습을 재미있다고 느끼는가?
5. 네 종류의 의상을 모두 선택하고 결과 화면까지 도달할 수 있는가?
6. 점수만 확인하는 데서 끝나지 않고 왜 그 옷이 알맞은지 설명할 수 있는가?
7. 새로운 상황 문제에 배운 기준을 다시 적용할 수 있는가?
8. 다시 코디하거나 다음 에피소드를 플레이하고 싶어 하는가?

## 2. 테스트 범위

### 포함

- 시작 화면
- 로그인 모형 화면에서 `게스트로 시작`
- 스토리 모드와 1화 선택
- 문자 상황 읽기
- 90초 옷입히기
- 의상 4개 카테고리와 카테고리별 4개 선택지
- 캐릭터 의상 합성
- 점수와 TPO 설명
- 새 상황 문제
- 2화 해제와 재도전 의향
- 데스크톱 또는 태블릿 2명 이상, 모바일 1명 이상

### 제외

- 실제 로그인
- Supabase 연동
- 배틀 모드
- 결제, 광고, 공유 기능
- 2화 이후 콘텐츠의 세부 난이도 평가

## 3. 통과 기준

참여자가 5명일 때의 기준이다. 3명만 참여하면 비율과 행동 기록을 함께 판단한다.

| 측정 항목 | 통과 기준 |
|---|---:|
| 설명 없이 게스트로 게임 시작 | 4명 이상 |
| T·P·O 중 2개 이상 정확히 말함 | 4명 이상 |
| 겉옷·하의·신발·소품 네 카테고리를 모두 사용 | 4명 이상 |
| 의상 그림의 종류를 읽기 전에 구분 | 전체 관찰의 80% 이상 |
| 1화 결과 화면까지 자력 도달 | 4명 이상 |
| 적절한 옷의 이유를 2가지 이상 설명 | 4명 이상 |
| 새 상황 문제의 정답 선택 | 4명 이상 |
| 캐릭터 변화에 긍정 반응 | 4명 이상 |
| 다시 플레이하거나 다음 화를 원함 | 4명 이상 |
| 치명적 진행 중단 문제 | 0건 |

점수는 어린이의 능력을 평가하는 값이 아니라 게임의 설명력과 조작성을 판단하는 보조 지표로만 사용한다.

## 4. 테스트 전 준비

### 기기 준비

- 최신 배포 주소가 열리는지 확인한다.
- 브라우저 확대 비율은 100%로 맞춘다.
- 한 기기를 여러 어린이가 사용할 때는 새 브라우저 프로필이나 시크릿 창을 사용한다.
- 이전 참여자의 최고 점수와 2화 해제 기록이 다음 참여자에게 보이지 않게 한다.
- 마우스와 터치 기기를 가능하면 모두 포함한다.
- 소리는 현재 핵심 평가 대상이 아니므로 음소거 상태여도 된다.

### 안전과 개인정보

- 이름, 학교, 연락처를 기록하지 않는다.
- 화면·얼굴·목소리 녹화는 보호자와 참여자의 동의를 모두 받은 경우에만 한다.
- 동의가 없으면 관찰자가 시간과 행동만 기록한다.
- 어린이에게 점수가 낮아도 실패하거나 평가받는 것이 아니라고 먼저 설명한다.
- 참여자가 중단하고 싶어 하면 이유를 묻지 않고 즉시 종료한다.

### 진행자 준비

- 한 명은 진행, 한 명은 관찰을 권장한다.
- 진행자는 정답을 알려 주거나 특정 버튼을 가리키지 않는다.
- 어린이가 10초 이상 멈췄을 때만 중립적인 질문을 한다.
- 칭찬은 점수보다 생각한 과정에 대해 한다.

## 5. 1명당 진행 대본

### 0단계 — 소개, 1분

진행자:

> 이 게임이 사용하기 쉬운지 알아보려고 해요. 네가 시험을 보는 게 아니라 게임을 시험하는 거예요. 모르는 것이 있으면 그대로 말해 주세요.

### 1단계 — 자유 시작, 2분

사이트의 첫 화면만 보여 주고 말한다.

> 지금부터 네가 하고 싶은 대로 시작해 봐.

관찰:

- `구조대 입단하기`를 찾는 시간
- 모형 로그인 화면에서 `게스트로 시작`을 찾는지
- 스토리 모드를 스스로 선택하는지
- 1화를 스스로 여는지
- 멈춤, 잘못된 클릭, 되돌아가기 횟수

도움이 필요할 때 사용할 중립 문장:

> 지금 화면에서 다음에 할 수 있는 일이 무엇처럼 보여?

### 2단계 — 문자와 TPO 이해, 3분

어린이가 문자를 읽은 뒤 질문한다.

> 언제 가는 것 같아?

> 어디에서 하는 일이야?

> 거기에서 무엇을 해야 해?

추가 질문:

> 옷을 고를 때 가장 중요하게 생각해야 할 것은 무엇일까?

정답을 유도하는 단어인 `안전`, `잘 보임`, `활동성`을 먼저 말하지 않는다.

### 3단계 — 옷입히기, 5분

진행자:

> 이제 네가 알맞다고 생각하는 옷을 입혀 봐. 고르는 동안 생각나는 것을 말해 줘도 좋아.

관찰:

- 시작 버튼을 바로 찾는지
- 90초 표시에 압박을 느끼는지
- 네 카테고리를 모두 이해하는지
- 그림을 먼저 보는지, 설명을 먼저 읽는지
- 의상을 선택했을 때 캐릭터 변화에 반응하는지
- 상의와 하의 연결부를 이상하다고 느끼는지
- 잘못 고른 뒤 다른 옷으로 쉽게 바꾸는지
- 0초가 된 뒤에도 계속 선택할 수 있음을 이해하는지
- 4개를 고르기 전에 출발 버튼을 누르는지

10초 이상 멈추면:

> 아직 확인하지 않은 곳이 있을까?

사용하지 말아야 할 말:

- “하의를 눌러 봐.”
- “운동화가 정답이야.”
- “네 개를 다 골라야 해.”

### 4단계 — 결과와 이유 설명, 3분

결과 화면에서 먼저 자유롭게 보게 한 뒤 질문한다.

> 이 점수에서 제일 먼저 본 것은 무엇이야?

> 네가 고른 옷이 왜 이 상황에 잘 맞는지 설명해 줄래?

> 바꾸고 싶은 옷이 있다면 무엇이고, 왜 바꾸고 싶어?

필요할 때만:

> 잘 보이는 것, 움직이는 것, 몸을 보호하는 것 중 생각나는 것이 있어?

### 5단계 — 새로운 상황 적용, 2분

진행자:

> 아래 새 상황 문제도 네가 생각해서 골라 봐.

관찰:

- 예시 설명을 먼저 여는지
- 비 오는 저녁 상황에서 `비를 막고 앞이 잘 보이는 기능`을 선택하는지
- 기존 1화의 정답을 외워서 고르는지, 새 상황의 이유를 말하는지

### 6단계 — 마무리 인터뷰, 3분

질문은 한 번에 하나씩 한다.

1. 가장 재미있었던 것은 무엇이야?
2. 가장 어려웠거나 헷갈렸던 것은 무엇이야?
3. 옷 그림 중 무엇인지 알아보기 어려운 것이 있었어?
4. 캐릭터에게 옷을 입히는 느낌은 어땠어?
5. 점수가 왜 그렇게 나왔는지 알겠어?
6. 다시 코디해 보고 싶어, 아니면 다음 이야기를 해 보고 싶어?
7. 한 가지만 바꿀 수 있다면 무엇을 바꾸고 싶어?

## 7. 문제 심각도 기준

| 등급 | 의미 | 예시 | 처리 |
|---|---|---|---|
| S0 | 테스트 진행 불가 | 화면이 열리지 않음, 제출 불가 | 즉시 수정 후 테스트 중단 |
| S1 | 핵심 학습 또는 진행 실패 | 다수가 시작 버튼을 못 찾음, 의상을 구분하지 못함 | 다음 에피소드 전에 수정·재시험 |
| S2 | 반복되는 혼란 | 카테고리를 자주 놓침, 점수 이유를 이해하지 못함 | 우선순위 보정 |
| S3 | 미세한 불편 또는 선호 | 문구, 간격, 색상 선호 | 묶어서 개선 |

한 명에게만 나타난 문제라도 진행을 막으면 S1 이상으로 기록한다. 여러 명에게 반복되면 심각도를 한 단계 올려 검토한다.

## 8. Gate 7 내부 QA에서 나온 사전 관찰 지점

아래 항목은 실제 어린이 결과가 아니라 성인 관점의 사전 점검이다. 플레이테스트에서 확인하기 전까지 사용자 문제로 단정하지 않는다.

1. 모바일 390px에서 가로 넘침은 없고 의상 카드가 2×2로 표시된다.
2. 모바일 문자 화면은 세로로 길어 시작 버튼을 보기 위해 스크롤이 필요할 수 있다.
3. `이 코디로 출발!` 버튼은 0/4 상태에서도 보이므로 조기 제출이 발생하는지 관찰해야 한다.
4. 시간이 0초가 되어도 선택은 계속되지만 어린이가 이를 알아차릴 수 있는 안내는 없다.
5. 결과 화면은 점수, 이유 설명, 새 상황 문제까지 길게 이어지므로 아래 콘텐츠를 놓치는지 관찰해야 한다.
6. 게스트 진행 기록이 브라우저에 남으므로 참여자마다 새로운 세션을 준비해야 한다.
7. 의상 16종, 90초 타이머, 0초 이후 선택, 채점, 설명 예시, 새 상황 문제와 2화 해제는 기능 QA를 통과했다.

## 10. Gate 판정

### 통과

- S0·S1 문제가 없다.
- 핵심 통과 기준을 모두 충족한다.
- 어린이가 코디 이유를 말할 수 있다.
- 다음 에피소드 제작에 현재 에셋·게임 구조를 재사용한다.

### 조건부 통과

- S1 문제는 없지만 두 개 이하의 핵심 지표가 기준에 미달한다.
- 해당 문제만 수정한 뒤 2~3명으로 짧게 재시험한다.

### 재설계

- S0 또는 반복되는 S1 문제가 있다.
- 의상 그림을 구분하지 못하거나 TPO 이유를 설명하지 못한다.
- 다른 에피소드 확장을 멈추고 1화를 먼저 수정한다.

## 11. 테스트 후 수정 원칙

1. 발화보다 행동을 우선한다. “재미있다”고 말해도 반복해서 막혔다면 문제로 기록한다.
2. 한 명의 취향 때문에 전체 디자인을 바꾸지 않는다.
3. 두 명 이상에게 반복된 문제를 우선 수정한다.
4. 안전과 학습 이해 문제는 시각적 선호보다 먼저 수정한다.
5. 실제 어린이 증거 없이 의상 시스템 전체를 다시 만들지 않는다.
6. 수정 후에는 문제를 발견한 과업만 재시험하고, 핵심 흐름 회귀 테스트를 함께 실행한다.

플레이테스트 결과를 이 문서의 집계표에 입력한 뒤 다음 중 하나를 선택한다.

- Gate 통과: 1화 구조를 에피소드 공통 템플릿으로 고정하고 2~13화 에셋을 확장한다.
- 조건부 통과: 모바일 시작 버튼, 조기 제출, 시간 종료 안내, 결과 화면 길이 중 확인된 문제만 보정한다.
- 재설계: 1화의 의상 인지성·캐릭터 반응·TPO 설명 방식을 우선 수정한다.

로그인과 Supabase 연동은 전체 에피소드의 핵심 게임 흐름이 검증된 뒤 진행한다.
