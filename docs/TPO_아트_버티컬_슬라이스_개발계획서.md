# TPO 아트 버티컬 슬라이스 개발계획서

> 문서 상태: 실행 계획 v1.0
> 대상: 스토리 모드 에피소드 1 `비 오는 날 마트 심부름`
> 권장 기간: 10영업일
> 핵심 목표: 그림을 추가하는 것이 아니라, 옷을 계속 확장할 수 있는 에셋 시스템을 검증한다.

## 1. 이번 단계의 결정

현재 CSS 캐릭터는 기능 검증용 안전망으로 유지하고, 첫 번째 에피소드에만
레이어형 이미지 캐릭터와 의상 에셋을 적용한다.

이번 단계에서 검증할 가설은 다섯 가지다.

1. 아이가 글을 읽기 전에 아이템의 종류와 기능을 구분한다.
2. 옷을 선택할 때 캐릭터 외형이 확실히 바뀌어 재미를 느낀다.
3. 점수뿐 아니라 시간·장소·상황과 옷의 기능을 연결해 설명한다.
4. 다른 조합으로 다시 코디하거나 다음 이야기를 하고 싶어 한다.
5. 새 아이템은 공통 화면 코드를 수정하지 않고 추가할 수 있다.

## 2. 범위

### 2.1 포함

- 기준 캐릭터 1종
- 기본·성공·아쉬움 표정 3종
- 현재 상의 4종
- 현재 하의 4종
- 현재 신발 4종
- 현재 소품 4종
- 비 오는 저녁 배경 1종
- 빗줄기와 반사광 효과
- 실제 그림이 들어간 옷장 카드
- 레이어형 캐릭터 렌더러
- 이미지 실패 시 기존 CSS 캐릭터로 돌아가는 안전장치
- 모바일·태블릿·데스크톱 대응
- 접근성·성능·조합 검증
- 아동 사용성 테스트와 Go/Revise/No-go 판정

### 2.2 제외

- 에피소드 2 제작
- 배틀 모드
- 실제 로그인
- Supabase
- 랭킹·상점·아이템 수집
- 추가 캐릭터
- 음성 안내와 고급 애니메이션
- 전체 12개 에피소드의 배경과 의상

진행도와 최고점은 현재처럼 `localStorage`에 저장한다.

## 3. 핵심 제작 원칙

### 3.1 완성 코디를 조합별로 그리지 않는다

상의·하의·신발·소품이 각각 4개이면 가능한 조합은 256개다. 완성 코디를
256장 만드는 대신, 몸과 옷을 분리하여 브라우저가 겹쳐 그리도록 한다.

```text
배경
→ 뒤쪽 빗줄기
→ 우산·가방의 뒤쪽
→ 우비 후드의 뒤쪽
→ 캐릭터 몸
→ 하의
→ 신발
→ 상의
→ 얼굴 표정
→ 우산 손잡이·가방끈·반사 밴드
→ 반사광
→ 앞쪽 빗줄기
```

### 3.2 옷장과 착용 화면은 같은 원본을 사용한다

아이템 카드용 그림과 캐릭터 착용용 그림을 따로 그리지 않는다. 하나의
벡터 원본에서 착용 레이어와 카드 썸네일을 파생한다.

### 3.3 교육·채점 데이터와 그림 데이터를 분리한다

- 게임 데이터: 이름, 설명, 슬롯, TPO 태그, 채점 속성
- 아트 데이터: 이미지 경로, 레이어 순서, 기준 좌표, 썸네일

이미지를 수정해도 점수가 바뀌지 않고, 채점 규칙을 수정해도 옷 위치가
바뀌지 않아야 한다.

### 3.4 오답도 매력적으로 표현한다

슬리퍼나 긴 치마는 항상 나쁜 옷이 아니다. `비 오는 저녁 심부름`이라는
현재 상황에서 덜 적절할 뿐이다. 오답 아이템을 못생기거나 우스꽝스럽게
표현하지 않는다.

## 4. 에셋 제작 규격

### 4.1 기준 캐릭터

- 정면 고정 포즈
- 양발은 겹치지 않고 지면에 평행하게 배치
- 양팔은 몸통에서 약 12도 떨어뜨림
- 오른손은 우산 손잡이를 잡을 수 있는 위치
- 왼쪽 어깨와 손은 장바구니 공간 확보
- 긴 치마·반바지·장화의 실루엣이 모두 보이는 체형
- 첫 번째 아트 시스템이 승인될 때까지 포즈 변경 금지

### 4.2 공통 캔버스

| 항목 | 규격 |
|---|---|
| 원본 캔버스 | 1024 × 1536px |
| 런타임 이미지 크기 | 1024 × 1536px |
| 화면 기본 표시 | 256 × 384 CSS px |
| 전역 기준점 | 하단 중앙 `(512, 1440)` |
| 정렬 | `xMidYMax meet` |
| 배경 | 투명 |
| 색상 공간 | sRGB |
| 원본 앵커 허용 오차 | ±8px |

모든 착용 WebP는 같은 캔버스와 기준점을 유지한다. 각 파일의 옷 부분만
잘라 저장하지 않는다.

### 4.3 주요 앵커

| 앵커 | 좌표 |
|---|---:|
| 머리 중심 | `(512, 320)` |
| 왼쪽 어깨 | `(350, 610)` |
| 오른쪽 어깨 | `(674, 610)` |
| 왼쪽 손 | `(270, 940)` |
| 오른쪽 손 | `(754, 940)` |
| 허리 중심 | `(512, 915)` |
| 왼쪽 발목 | `(420, 1380)` |
| 오른쪽 발목 | `(604, 1380)` |
| 지면 중심 | `(512, 1440)` |

이 좌표는 골든 세트 통합 과정에서 한 번 조정할 수 있다. 골든 세트가
승인된 이후에는 변경하지 않는다.

### 4.4 시각 스타일

- 현재 UI와 어울리는 단순한 2D 플랫 벡터
- 외곽선은 검정보다 부드러운 네이비
- 원본 기준 외곽선 8px, 내부선 5px
- 네이비·코럴·노랑·민트·크림 중심의 제한된 팔레트
- 작은 화면에서도 옷 종류를 실루엣으로 구분
- 재질 표현은 방수·보온·반사처럼 학습에 필요한 범위로 제한
- 반실사, 복잡한 주름, 과도한 질감과 장식은 사용하지 않음
- 색만 달라지는 복제 아이템을 만들지 않음

### 4.5 이미지 형식

| 용도 | 형식 | 기준 |
|---|---|---|
| 캐릭터·의상·소품·표정·효과 | 투명 WebP | 1024×1536 공통 캔버스 |
| 에피소드 배경 | WebP | 1920×1440, 300KB 이하 |
| 옷장 썸네일 | WebP | 512×384, 35KB 이하 |
| 검수 중간 파일 | PNG 허용 | 런타임에는 포함하지 않음 |

이미지 안에는 아이템 이름, 점수, 정답 표시, UI 문구를 넣지 않는다.

## 7. 파일 구조와 이름

```text
public/art/v1/
├─ character/
│  ├─ base.webp
│  └─ faces/
│     ├─ ready.webp
│     ├─ success.webp
│     └─ retry.webp
├─ episodes/
│  └─ rainy-market-errand/
│     ├─ background.webp
│     └─ effects/
│        ├─ rain-back.webp
│        ├─ rain-front.webp
│        └─ reflective-glow.webp
├─ items/
│  ├─ yellow-raincoat/
│  │  ├─ wear-back.webp
│  │  ├─ wear-main.webp
│  │  └─ thumb.webp
│  ├─ clear-umbrella/
│  │  ├─ wear-back.webp
│  │  ├─ wear-front.webp
│  │  └─ thumb.webp
│  └─ ...
└─ art-manifest.json
```

규칙:

- 폴더명은 기존 아이템 ID와 동일
- 영문 소문자와 하이픈만 사용
- `final`, `new`, `수정본`과 같은 단어를 파일명에 사용하지 않음
- 버전은 파일명이 아니라 `v1`, `v2` 상위 폴더로 관리
- 단일 레이어는 `wear-main.webp`
- 뒤쪽 레이어는 `wear-back.webp`
- 앞쪽 레이어는 `wear-front.webp`
- 썸네일은 `thumb.webp`

## 8. 아트 카탈로그와 렌더러

`art-manifest.json`은 옷 그림을 게임과 연결하는 카탈로그다.

```json
{
  "schemaVersion": 1,
  "artVersion": "v1",
  "canvas": { "width": 1024, "height": 1536 },
  "items": {
    "clear-umbrella": {
      "slot": "accessory",
      "thumbnail": "items/clear-umbrella/thumb.webp",
      "layers": [
        {
          "src": "items/clear-umbrella/wear-back.webp",
          "plane": "accessoryBack",
          "order": 0
        },
        {
          "src": "items/clear-umbrella/wear-front.webp",
          "plane": "accessoryFront",
          "order": 0
        }
      ]
    }
  }
}
```

렌더러는 다음 책임만 가진다.

- 선택한 아이템 ID로 필요한 레이어 찾기
- 중앙 레이어 규칙에 따라 순서 정렬
- 모든 레이어를 같은 비율로 확대·축소
- 새 이미지가 준비된 뒤 한 번에 착장 교체
- 이미지 실패 시 기존 CSS 캐릭터 표시

새 아이템을 추가할 때 렌더러, 옷장 카드, 전역 CSS의 아이템별 코드를
수정하지 않아야 한다.

## 9. 기존 게임의 변경 전략

기존 선택·채점·타이머·문자·결과 로직은 유지하고 표현 계층만 교체한다.

```text
Character
├─ ImageCharacterRenderer
└─ LegacyCssCharacter
```

초기 운영 방식은 `auto`로 둔다.

- 이미지 에셋이 정상이면 새 렌더러 사용
- 매니페스트 또는 핵심 이미지가 실패하면 CSS 캐릭터 사용
- 이미지와 CSS 옷을 한 캐릭터 안에서 섞지 않음

옷장 카드는 실제 썸네일을 표시하되 품목명, 기능 설명, 체크 표시,
`입는 중` 문구를 그대로 유지한다.

## 10. 성능과 접근성 기준

### 10.1 성능 예산

| 대상 | 상한 |
|---|---:|
| 기본 캐릭터와 표정 | 300KB |
| 의상 레이어 1개 | 평균 60KB, 최대 100KB |
| 썸네일 1개 | 35KB |
| 배경 | 300KB |
| 최초 아트 전송량 | 700KB |
| 첫 옷장 탭까지 누적 | 1MB |
| 에피소드 전체 아트 | 2MB |

- 현재 캐릭터와 열린 탭을 우선 로딩
- 다른 탭은 열 때 로딩
- 카드 포커스·터치 시작 시 착용 레이어 미리 준비
- 캐시된 아이템은 선택 후 150ms 이내 반영
- 처음 선택한 아이템도 500ms 이내 반영
- 이미지 때문에 화면 배치가 움직이지 않게 크기 고정

### 10.2 접근성

- 개별 장식 레이어는 스크린리더에서 숨김
- 캐릭터 전체를 한 문장으로 설명
- 선택 변경은 `aria-live`로 짧게 알림
- 카드의 품목명·설명·`aria-pressed` 유지
- 선택 상태를 색, 체크, 테두리, 문구로 중복 표현
- 키보드만으로 모든 코디 가능
- 모션 감소 설정에서는 착용 효과 제거
- 터치 영역 최소 44×44px

| 2 | 기본 캐릭터와 골든 세트 제작 | 최소 이미지 렌더러와 CSS 폴백 | 테스트 조합·접근성 체크리스트 | 내부 정렬 점검 |
| 3 | 골든 세트 수정 | 선택·착용·결과 화면 연결 | 모바일·데스크톱 확인 | **Gate A: 골든 세트 승인** |
| 4 | 남은 상의·하의 제작 | 실제 썸네일 카드 전환 | 아이템 무문자 식별 사전 검토 |  |
| 5 | 남은 신발·소품 제작 | 로딩·오류 상태 처리 | 기능 단서·오답 표현 검수 |  |
| 6 | 표정·배경·효과와 전체 최적화 | 16종 매니페스트 연결 | 256개 조합 자동 검수 | 전체 에셋 1차 승인 |
| 7 | 겹침·클리핑 수정 | 결과 화면·반응형·localStorage 회귀 | 키보드·스크린리더 점검 |  |
| 8 | 최종 아트 보정 | 성능·캐싱·빌드 검사 | 전체 기능·접근성 회귀 | **Gate B: 테스트 버전 동결** |
| 9 | 파일럿 피드백 수정 | 치명·주요 문제 수정 | 아동 2명 파일럿 | 파일럿 승인 |
| 10 | v1 에셋 동결 | 최종 검증·배포 후보 생성 | 아동 5~8명 또는 예약된 검증, 판정 | **Gate C: Go/Revise/No-go** |

아동 모집 일정이 맞지 않으면 8일차까지 개발 후보를 동결하고, 9~10일차
검증만 별도 일정으로 진행한다. 테스트를 생략한 상태에서는 에피소드 2를
시작하지 않는다.

## 13. 우선순위

### P0

- 기준 캐릭터와 골든 세트
- 16개 아이템의 식별 가능한 그림
- 선택 즉시 착용 결과 반영
- 실제 그림이 들어간 옷장 카드
- 고정 레이어 규칙과 매니페스트
- CSS 폴백
- 모바일·데스크톱 정렬
- 점수·타이머·localStorage 회귀 없음
- 색 이외의 선택 상태 표시
- 아동 테스트와 Go/Revise/No-go 판정

### P1

- 성공·아쉬움 표정
- 빗방울과 반사광
- 착용 시 짧은 시각 피드백
- 아이템 확대 보기
- 다시 코디하기 동선 개선

### P2

- 고급 애니메이션
- 음향과 음성
- 추가 캐릭터
- 배경 변형
- 아이템 도감
- 수집 연출

P0 문제가 남아 있으면 P2를 시작하지 않는다.

## 14. 검증 계획

### 14.1 자동·기능 검증

- 모든 게임 아이템 ID가 매니페스트에 존재
- 참조한 이미지 파일이 실제로 존재
- 게임 슬롯과 아트 슬롯이 일치
- 레이어 순서와 경로가 유효
- 256개 조합에서 치명적인 겹침·클리핑이 없음
- 각 아이템 단독 착용 화면 검증
- 추천 코디와 최저점 코디 검증
- 우산·가방·반사 밴드의 앞뒤 관계 검증
- 모두 벗기기, 재시도, 타이머 종료, 결과 화면 검증
- 이미지 실패 시 CSS 폴백 검증
- 모바일 360×800, 태블릿 768×1024, 데스크톱 1440×900 검증

### 14.2 아동 검증

권장 대상은 초등 아동 5~8명이며, 문제 발견을 위한 소규모 형성평가로
사용한다. 보호자 동의를 받고 불필요한 개인정보는 수집하지 않는다.

과업:

1. 이름을 가린 아이템 그림 식별
2. 문자에서 시간·장소·상황 설명
3. 도움 없이 첫 코디 완성
4. 아이템 교체 후 캐릭터 변화 설명
5. 선택 이유를 상황과 기능으로 설명
6. 비가 그치거나 장소가 바뀐 상황에 코디 적용
7. 다시 코디 또는 다음 이야기 의향 확인

진행자는 정답을 유도하지 않는다.

### 14.3 성공 지표

| 지표 | 목표 |
|---|---:|
| 전체 아이템 그림 식별률 | 85% 이상 |
| 우비·장화·투명 우산·반사 밴드 식별률 | 각 90% 이상 |
| 도움 없는 코디 완료율 | 90% 이상 |
| 선택 후 캐릭터 변화 인지율 | 90% 이상 |
| 선택·해제·교체 성공률 | 85% 이상 |
| TPO 중 2개 이상 파악 | 아동의 80% 이상 |
| 아이템 기능과 상황을 연결한 이유 설명 | 아동의 80% 이상 |
| 다시 코디하거나 다음 이야기를 원함 | 아동의 75% 이상 |
| 재미 평가 | 5점 척도 중앙값 4 이상 |
| 새 아이템 등록 시간 | 그림 제작 제외 30분 이내 |
| 새 아이템을 위한 공통 화면 코드 수정 | 0건 |

## 15. 판정 기준

### Go

- 모든 P0 항목 완료
- 핵심 아이템 식별과 TPO 이유 설명 목표 달성
- 치명적 레이어·조작 오류 0건
- 재플레이 의향 75% 이상
- 새 아이템을 공통 코드 수정 없이 추가 가능

### Revise

- 특정 2~3개 아이템에서만 혼동이 집중됨
- 목표 지표 1~2개가 기준보다 10%포인트 이내로 부족함
- 캐릭터 변화는 보이지만 선택·해제가 불명확함
- TPO 단서는 찾지만 아이템 기능과 연결하지 못함
- 레이어 구조는 동작하지만 제작 규칙이나 성능 개선이 필요함

Revise이면 1~2주 수정 후 실패한 핵심 과업만 다시 검증한다.

### No-go

- 핵심 아이템 다수가 그림으로 구분되지 않음
- 아트 적용 후에도 글자 정답 맞히기처럼 행동함
- 캐릭터 변화 인지율이 70% 미만
- 그림이 안전 관련 오개념을 반복적으로 유발함
- 새 아이템마다 React 조건문이나 전용 CSS가 필요함
- 기존 CSS 버전보다 이해도·재미가 뚜렷하게 개선되지 않음

|---|---|

| AI로 아이템을 개별 생성해 스타일이 달라짐 | AI는 무드보드·콘셉트에만 사용, 최종은 동일 원본에서 벡터 정리 |

## 17. 완료 기준

다음을 모두 만족하면 아트 버티컬 슬라이스를 완료한 것으로 본다.

- 16개 아이템이 옷장과 캐릭터에서 같은 원본으로 표현됨
- 모든 256개 조합이 위치 오류 없이 표시됨
- 우산·가방의 앞뒤 관계가 정확함
- 그림 없이도 품목명과 설명으로 같은 정보를 얻을 수 있음
- 새 아이템 추가 시 렌더러·카드·전역 CSS 수정이 없음
- 이미지 오류 시 CSS 캐릭터로 복구됨
- 기존 점수·타이머·선택 로직에 회귀 오류가 없음
- Supabase 없이 모든 흐름이 동작함
- 전체 에피소드 아트가 2MB 이하
- 키보드·스크린리더·모바일 테스트 통과
- 아동 검증에서 아이템 식별·TPO 설명·재플레이 목표 충족
- 아트 원본, 파일명, 좌표, 권리, 버전 기록이 남아 있음

## 18. 에피소드 2 시작 게이트

에피소드 2는 다음 조건을 모두 통과한 뒤 시작한다.

1. Gate C가 Go로 판정된다.
2. P0 사용성·교육·접근성 문제가 모두 해결된다.
3. 기준 캔버스·앵커·레이어·파일명·내보내기 규칙이 문서화된다.
4. 시험용 신규 아이템 1개가 카드·착용·결과 화면에 자동 반영된다.
5. 신규 아이템 추가에 공통 화면 코드 수정이 필요 없다.
6. 에피소드 2의 예상 에셋 수와 제작 시간이 산정된다.

이번 단계의 성공은 첫 번째 에피소드의 그림을 완성하는 데 그치지 않는다.
두 번째 에피소드를 더 빠르고 안정적으로 추가할 수 있는 제작 규칙을
검증하는 것이 최종 성공이다.

## 19. 승인 후 첫 작업

계획이 승인되면 첫 작업은 전체 44개 에셋 제작이 아니다.

1. 현재 CSS 버전의 기준 화면을 보존한다.
2. 기준 캐릭터 포즈·캔버스·앵커를 확정한다.
3. 스타일 방향 2~3안을 비교해 하나를 고정한다.
4. 아래 골든 세트를 먼저 제작한다.
   - 노란 우비
   - 검정 활동 바지
   - 노란 장화
   - 투명 우산
5. 골든 세트가 옷장·착용·결과 화면에 정확히 재사용되는지 확인한다.
6. Gate A를 통과한 뒤에만 나머지 12개 아이템을 제작한다.
