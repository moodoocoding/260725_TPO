# TPO 13화 아동 UX 대리검증 계획

- 작성일: 2026-07-27
- 대상: 스토리 모드 1~13화, 챕터 도입·엔딩·최종 엔딩
- 기준 화면: 데스크톱과 모바일 `390×844`
- 검토 파일: `lib/story-narrative.ts`, `lib/story-catalog.json`, `app/page.tsx`, `app/globals.css`, `components/story-cutscene.tsx`
- 단계: 실제 브라우저 시뮬레이션 전 정적 감사와 실행 계획

> 이 문서는 실제 어린이의 행동 기록이 아니다. 코드와 콘텐츠를 바탕으로 네 가지 합성 페르소나의 행동을 미리 정의한 사전 검증 계획이며, 실제 아동 플레이테스트를 대체하지 않는다.

## 1. 검증 목적

다음 질문에 답하는 것을 목표로 한다.

1. 저학년이 컷신 한 화면의 글을 읽거나 건너뛰고도 다음 행동을 찾는가?
2. `이전 장면`, `이야기 건너뛰기`, `다음 장면`의 결과가 예측과 일치하는가?
3. 요청을 보낸 사람과 실제로 옷을 입는 캐릭터가 구분되는가?
4. 13화 모두 겉옷·하의·신발·소품별 네 선택지를 제공하는가?
5. 네 선택지가 단순히 첫 카드만 눌러도 이기는 배열이 아니라 TPO 판단을 요구하는가?
6. `390×844` 화면에서 컷신, 문자, 의상 선택, 결과, 재도전의 주 행동이 발견되는가?
7. 실패 후 무엇을 고쳐야 하는지 이해하고 짧은 경로로 다시 시도할 수 있는가?
8. 챕터 엔딩과 13화 최종 엔딩이 실제 진행 중 나타나고 다시 볼 수 있는가?

## 2. 정적 감사 요약

### 2.1 확인된 장점

- 13화 모두 네 슬롯을 사용한다.
- 52개 슬롯 그룹 모두 선택지가 정확히 4개다.
- 문자 상황은 에피소드마다 네 개의 짧은 말풍선으로 구성돼 있다.
- 컷신에는 이전, 다음, 건너뛰기 버튼과 장면 진행 표시가 준비돼 있다.
- 스토리 맵에는 이미 본 챕터 이야기를 다시 여는 진입점이 준비돼 있다.
- 모바일 옷장에는 축소 캐릭터 미리보기와 슬롯 탭이 고정되도록 설계돼 있다.
- 실패 결과 상단에 빠른 재도전 버튼이 배치돼 있다.
- 옷입히기 타이머는 화면 진입이 아니라 첫 아이템 선택 때 시작하도록 보정돼 있다.
- 실패 후 재도전은 직전 코디를 유지해 부족한 슬롯만 수정할 수 있다.
- 에피소드 성공 후 이야기, 실패 문장, 다음 훅이 결과 화면에 연결돼 있다.
- 챕터 마지막 화에는 챕터 마무리 또는 최종 엔딩으로 가는 버튼이 연결돼 있다.
- 옷입히기와 결과 캐릭터에 실제 착용자 이름이 전달된다.

### 2.2 통합 완료 전에 확인할 위험

아래 내용은 감사 시점의 정적 상태이며, 통합 작업 후 실제 브라우저에서 다시 판정한다.

| 우선순위 | 발견 사항 | 아동에게 미치는 영향 | 후속 검증 |

| S1 | 에피소드 결과의 다음 훅과 챕터 엔딩의 다음 훅이 연속 노출될 수 있음 | 같은 예고를 반복해 이야기 리듬이 늘어짐 | 1·4·7·10·13화 성공 후 중복 문장 확인 |

| S2 | 스토리 맵에는 챕터 도입 다시 보기만 있고 엔딩 다시 보기는 보이지 않음 | 엔딩을 놓치거나 다시 보고 싶은 재도전자가 접근하기 어려움 | 완료 챕터의 엔딩 재진입 경로 확인 |
| S2 | 컷신 장면표에 `visualKey` 영문 키가 그대로 노출됨 | 저학년에게 의미 없는 영문 정보가 주의를 빼앗음 | 한국어 장면명 또는 장식 처리 확인 |
| S2 | 마지막 안전 챕터 엔딩은 챕터 2장면, 최종 5장면, 다음 시즌 2장면으로 최대 9장면 | 건너뛰기 없는 긴 엔딩에서 이탈 가능 | 완주 시간, 이탈 지점, 건너뛰기 제공 확인 |

### 2.3 컷신 글자량 감사

`story-narrative.ts`의 컷신 대사는 총 120개다. 공백과 문장부호를 포함해 계산하면 다음과 같다.

- 45자를 넘는 대사: 21개
- 55자를 넘는 대사: 3개
- 가장 긴 대사: 80자

우선 분리 또는 축약 검토가 필요한 대사는 다음과 같다.

| ID | 글자 수 | 문제 |
|---|---:|---|
| `prologue-opening-3` | 80 | 배지 설명과 첫 질문이라는 두 생각이 한 화면에 있음 |
| `final-ending-3` | 64 | 세 가지 학습 내용을 한 문장에 동시에 회고함 |
| `school-pe-rush-intro-1` | 57 | 시간, 책상, 교과서, 체육 시간표 정보가 한 번에 제시됨 |

대사 기준은 다음과 같이 적용한다.

- 권장: 20~45자
- 주의: 46~55자
- 실패: 56자 이상
- 한 화면에는 한 가지 핵심 생각만 둔다.
- 저학년 기준 최대 두 문장, 모바일에서 최대 세 줄을 목표로 한다.
- 제목, 화자명, 대사, 진행 버튼을 합친 핵심 정보가 `390×844` 첫 화면에 보여야 한다.

### 2.4 네 선택지의 학습 타당성 감사

정적 데이터상 13화 모두 슬롯별 네 선택지를 충족한다. 그러나 현재 아이템 순서는 모든 에피소드에서 첫 카드가 가장 강한 후보로 배치돼 있다.

- 각 슬롯의 첫 카드만 선택하는 전략으로 13화 모두 통과 가능하다.
- 첫 카드 전략 점수는 전 에피소드에서 80~100점이다.
- 따라서 빠른 선택자는 옷의 기능을 이해하지 않고 위치만 학습할 수 있다.
- `best / acceptable / partial / mismatch` 역할이 명시된 에피소드는 현재 1화뿐이다.
- 최대 시간 보너스 기준 전체 256개 조합의 통과 비율은 에피소드별 약 6%~95%로 편차가 크다.

브라우저 검증 전에 다음 콘텐츠 게이트가 필요하다.

1. 13화의 모든 아이템에 `best / acceptable / partial / mismatch` 역할을 명시한다.
2. 52개 슬롯에서 최선 선택지 위치를 1~4번에 균형 있게 분산하거나 세션별로 안정적으로 섞는다.
3. 전부 최선인 코디는 90점 이상이어야 한다.
4. 전부 `acceptable`인 코디는 이야기 진행이 가능해야 한다.
5. `mismatch` 네 개를 고른 코디는 60점 미만이어야 한다.
6. 한 슬롯의 위험한 오답이 다른 슬롯의 태그로 완전히 상쇄되지 않아야 한다.
7. 같은 기능을 충족하는 여러 옷은 외형 취향 때문에 부당하게 오답 처리하지 않는다.

## 4. 공통 대리 시뮬레이션 절차

네 페르소나는 모두 1~13화를 수행한다. 각 실행은 별도 브라우저 프로필 또는 초기화된 `tpo-story-progress-v3` 상태에서 시작한다.

### 4.1 에피소드마다 반복할 기본 과제

1. 스토리 맵에서 해당 화를 연다.
2. 챕터 첫 화라면 챕터 도입을 보고 이전·다음·건너뛰기를 검사한다.
3. 에피소드 도입에서 다음 질문의 답을 기록한다.
   - 누가 부탁했는가?
   - 누구에게 옷을 입히는가?
   - 어디에서 무엇을 해야 하는가?
4. 문자 화면에서 T·P·O를 각각 한 가지씩 말한다.
5. 옷입히기 화면에서 네 슬롯을 모두 사용한다.
6. 각 슬롯에 선택지가 네 개 모두 있는지 확인한다.
7. 선택한 카드와 캐릭터 착용 결과가 같은 물건으로 보이는지 확인한다.
8. 제출 후 점수보다 먼저 “왜 이 옷이 맞거나 부족한가”를 말한다.
9. 실패 경로에서는 피드백을 보고 한 번 재도전한다.
10. 성공 경로에서는 새 상황 문제를 풀고 다음 화 또는 챕터 엔딩으로 이동한다.
11. 챕터 마지막 화에서는 엔딩, 다음 훅, 다음 챕터 도입 순서를 확인한다.
12. 13화에서는 최종 엔딩과 다음 시즌 훅까지 확인한다.

### 4.2 매 단계 기록값

- 첫 행동까지 걸린 시간
- 스크롤 거리와 방향
- 10초 이상 멈춘 횟수
- 잘못 누른 횟수
- 뒤로 가기 횟수
- 건너뛰기 사용 여부와 건너뛴 뒤 도착 화면
- 요청자와 착용자 답변
- 슬롯별 첫 선택과 최종 선택
- 선택 이유가 색·외형인지 기능·상황인지
- 카드와 착용 이미지가 같다고 인식했는지
- 시간 0초에서 보인 행동
- 실패 후 재도전 버튼 발견 시간
- 재도전에서 이전 선택을 기억하거나 비교할 수 있었는지
- 챕터 엔딩 완주 여부와 이탈 장면

## 5. 대리 사용자 네 유형

### P01 — 저학년 빠른 선택

#### 특성

- 그림을 먼저 보고 긴 글은 넘긴다.
- 첫 번째로 눈에 띄는 카드를 빠르게 누른다.
- 점수와 큰 버튼에 바로 반응한다.

#### 실행 절차

1. 챕터 도입은 첫 장면만 5초 보고 `건너뛰기`를 사용한다.
2. 에피소드 도입도 같은 방식으로 건너뛴다.
3. 문자는 끝까지 읽지 않고 큰 단서와 그림만 본다.
4. 각 슬롯에서 첫 번째 카드를 선택한다.
5. 네 슬롯을 모두 골라 즉시 제출한다.
6. 결과에서 가장 큰 버튼을 누른다.
7. 이 전략을 13화까지 반복한다.

#### 확인 목표

- 건너뛰어도 요청자, 착용자, 핵심 상황을 최소한으로 알 수 있는가?
- 첫 카드 전략만으로 13화가 연속 통과되지 않는가?
- 완료하지 않은 슬롯을 스스로 찾는가?
- 모바일에서 카드까지 스크롤하는 동안 타이머가 과도하게 줄지 않는가?
- 결과의 가장 큰 버튼이 의도한 다음 행동인가?

### P02 — 저학년 느린 읽기

#### 특성

- 모든 문장을 소리 내어 읽는다.
- 받침이 많거나 긴 문장에서 반복해서 읽는다.
- 타이머가 보이면 읽기를 포기할 수 있다.

#### 실행 절차

1. 모든 컷신 대사를 분당 약 120~150자 속도로 소리 내어 읽는 시간을 적용한다.
2. 각 장면에서 `이전 장면`을 한 번 사용한 뒤 다시 다음으로 간다.
3. 문자 네 개를 모두 읽고 T·P·O를 말한다.
4. 카드 이름과 설명을 네 장 모두 읽은 뒤 선택한다.
5. 두 개 슬롯에서는 0초까지 기다린 뒤 계속 선택할 수 있는지 확인한다.
6. 실패 시 피드백을 읽고 재도전한다.
7. 13화와 최종 엔딩까지 같은 방식으로 진행한다.

#### 확인 목표

- 컷신 대사가 모바일에서 세 줄 이하로 읽히는가?
- 이전 장면을 사용해도 장면 순서와 진행 기록이 망가지지 않는가?
- 시간 0초가 실패나 입력 잠금으로 오해되지 않는가?
- 읽기 속도 때문에 다음 화 해제가 불가능해지지 않는가?
- 장례식·결혼식 등 추상적인 예절 문장을 저학년 수준에서 설명할 수 있는가?

### P03 — 중학년 탐색 사용자

#### 특성

- 네 선택지를 비교하고 여러 옷을 입혀 본다.
- 정답보다 조합 변화와 이유를 탐색한다.
- 이전 이야기와 새 상황의 연결을 확인한다.

#### 실행 절차

1. 컷신을 모두 본 뒤 한 번은 이야기 다시 보기를 사용한다.
2. 각 슬롯의 네 카드를 차례로 눌러 착용 모습을 모두 확인한다.
3. 카드마다 “이 상황에서 좋은 점과 부족한 점”을 한 가지씩 기록한다.
4. `acceptable` 또는 `partial` 후보로 먼저 제출해 피드백을 본다.
5. 재도전에서 더 나은 조합으로 바꾼다.
6. 새 상황 전이 문제를 풀고 다음 화로 간다.
7. 각 챕터 엔딩에서 앞선 세 임무가 어떻게 묶였는지 한 문장으로 요약한다.

#### 확인 목표

- 네 카드가 시각적으로 구분되면서도 정답만 화려하게 강조되지 않는가?
- 카드 그림과 착용 그림의 색·길이·형태가 일치하는가?
- 여러 번 바꿔 입혀도 선택 상태와 타이머가 안정적인가?
- 부분정답 피드백이 “왜 부족한지”를 설명하는가?
- 챕터 엔딩이 앞선 학습을 회고하게 하는가?

### P04 — 재도전자

#### 특성

- 이전에 일부 에피소드를 완료했다.
- 최고 점수를 올리거나 놓친 이야기를 다시 보려 한다.
- 실패 후 정답을 외우는 대신 피드백으로 수정한다.

#### 실행 절차

1. 완료 기록이 있는 상태에서 스토리 맵을 연다.
2. 각 챕터의 `이야기 다시 보기`를 사용한다.
3. 13화 각각에서 의도적으로 `mismatch`가 포함된 코디를 제출한다.
4. 실패 결과에서 5초 안에 재도전 경로를 찾는다.
5. 재도전 시 이전 선택이 유지되는지 확인하고 부족한 슬롯만 수정한다.
6. 성공 후 최고 점수, 별, 완료 상태가 이전보다 낮아지지 않는지 확인한다.
7. 챕터 엔딩과 최종 엔딩을 다시 볼 수 있는지 확인한다.

#### 확인 목표

- 실패가 막다른 화면이 되지 않는가?
- 잘한 선택은 유지하고 부족한 선택만 고칠 수 있는가?
- `retryLine`이 실제 부족한 기능과 연결되는가?
- 이미 본 컷신을 건너뛰거나 다시 보는 선택권이 있는가?
- 재도전 후 잠금·해제·최고 점수가 일관되는가?

## 6. 모바일 `390×844` 전용 검사

각 페르소나는 최소 한 번 전 과정을 `390×844`, 확대 100%, 세로 방향으로 실행한다.

### 컷신

- 첫 화면에서 제목, 화자, 대사, `다음 장면`을 확인할 수 있어야 한다.
- `이전 장면`, `건너뛰기`, `다음 장면`의 터치 영역은 최소 `44×44px`이어야 한다.
- 세 버튼이 겹치거나 화면 밖으로 잘리지 않아야 한다.
- 대사 영역 내부에 별도 스크롤이 생기지 않아야 한다.
- 가로 넘침은 0px이어야 한다.

### 문자

- 마지막 문자 다음의 옷입히기 시작 버튼을 5초 안에 발견해야 한다.
- 시작 버튼이 첫 화면 밖에 있으면 아래에 행동이 있다는 명확한 표시가 필요하다.
- 요청자 이름과 “누구의 옷을 고르는지”가 같은 화면에 보여야 한다.

### 옷입히기

- 화면 진입 후 5초 안에 첫 의상 카드를 볼 수 있어야 한다.
- 캐릭터 변화와 현재 슬롯 상태를 선택 직후 확인할 수 있어야 한다.
- 네 카드는 2×2로 표시되고 가로 스크롤이 없어야 한다.
- 고정 캐릭터 미리보기와 슬롯 탭이 제출 바를 가리지 않아야 한다.
- 60초 에피소드에서 UI 탐색 때문에 잃는 시간은 5초 이하여야 한다.

### 결과와 재도전

- 실패 시 `다시 코디하기`가 첫 화면에 보여야 한다.
- 성공 시 이유 설명 또는 새 상황으로 가는 안내가 첫 화면에 보여야 한다.
- 결과 페이지가 길어도 아래에 학습 활동이 있다는 표시가 있어야 한다.
- 뒤로 가기나 재도전 후 스크롤 위치가 엉뚱한 중간 지점에 남지 않아야 한다.

### 7.4 챕터 엔딩 기준

- 다음 훅의 화자·캐릭터 이름·그림이 다음 요청자와 일치한다.
- 일반 챕터 엔딩은 4장면 이내를 권장한다.
- 최종 엔딩은 6장면 이내로 줄이거나 건너뛰기·나중에 다시 보기 기능을 제공한다.
- 최종 엔딩 후 스토리 맵에는 13/13 완료와 네 배지 획득이 유지된다.

## 8. 중단·수정 판정

다음 중 하나라도 발생하면 전편 브라우저 시뮬레이션을 중단하고 먼저 수정한다.

1. 챕터 엔딩 또는 최종 엔딩에 진입할 수 없음
2. 요청자의 말과 표시된 캐릭터 이름이 다름
3. 1화에서 나래 대장과 하루의 역할을 구분할 단서가 없음
4. 모바일에서 다음 버튼이나 첫 의상 카드를 찾지 못함
5. 실패 후 재도전 경로가 첫 화면에 없음
6. 한 슬롯에 네 선택지가 모두 표시되지 않음
7. 카드와 착용 결과가 다른 물건처럼 보임
8. 첫 카드만 고르는 전략으로 13화 전체 통과
9. 56자 이상 컷신 대사가 모바일에서 네 줄 이상 표시됨
10. 최종 엔딩 9장면을 건너뛸 수 없고 완주 시간이 90초를 넘음
