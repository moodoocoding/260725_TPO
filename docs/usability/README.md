# TPO 아동 사용성 테스트 패키지

> 대상 빌드: 스토리 모드 에피소드 1 `비 오는 저녁, 마트 심부름`
> 권장 참가자: 초등 4~6학년 5~8명
> 1인 소요 시간: 15분
> 테스트 방식: 진행자 1명 + 관찰자 1명 권장
> 데이터 원칙: 이름·이메일·로그인 정보 수집 금지, 참가자 번호만 기록
> 제외 범위: Supabase, 실제 로그인, 에피소드 2, 배틀 모드

## 1. 패키지 구성

| 파일 | 용도 |
|---|---|
| `README.md` | 준비 사항, 진행 대본, 중립적 질문 |
| `item-identification-cards.md` | 글자 없이 아이템을 구분하는 화면 |
| `participant-observation-sheet.md` | 참가자 1명당 한 부 사용하는 기록지 |
| `result-decision-sheet.md` | 전체 결과 집계와 Go/Revise/No-go 판정 |

이번 테스트는 제품의 합격을 증명하는 통계 조사가 아니라, 첫 번째 아트
시스템에서 반복되는 이해·조작 문제를 발견하기 위한 진단 테스트다. 백분율과
함께 반드시 성공한 참가자 수를 기록한다.

## 2. 확인할 가설

1. 아이가 글자를 보기 전에 아이템의 종류와 기능을 구분한다.
2. 아이템 선택 직후 캐릭터가 바뀐 것을 알아차린다.
3. 문자 속 때·장소·상황을 옷의 기능과 연결해 설명한다.
4. 점수만 확인하는 데 그치지 않고 다른 코디를 시도하고 싶어 한다.
5. 안전 관련 그림과 피드백이 잘못된 일반화를 만들지 않는다.

## 3. 참가자 구성

가능하면 다음 특성이 한쪽으로 치우치지 않게 모집한다.

- 초등 4~6학년
- 스스로 문장을 읽는 아동과 읽기 지원이 필요한 아동
- 옷입히기 게임 경험이 있는 아동과 없는 아동
- 태블릿과 PC 사용 경험이 서로 다른 아동

참가자는 `P01`, `P02`처럼 번호로만 구분한다. 이름, 학교, 학급, 연락처는
기록지에 적지 않는다.

## 4. 아동 보호와 개인정보 원칙

- 테스트 전에 보호자 동의와 아동의 참여 의사를 확인한다.
- 아동은 언제든 이유를 말하지 않고 중단할 수 있다.
- 정답을 맞히는 시험이 아니라 게임을 개선하는 활동이라고 설명한다.
- 기본 기록은 행동 체크와 익명 메모만 사용한다.
- 음성·화면·영상 녹화는 기관 규정과 별도 보호자 동의가 있을 때만 한다.
- 로그인 화면에는 아무 정보도 입력하지 않는다.
- 테스트 결과를 앱이나 외부 데이터베이스로 전송하지 않는다.
- 놀림, 외모·체형 평가, 성별에 따른 옷 제한 표현을 사용하지 않는다.
- 안전에 관한 잘못된 이해가 확인되면 해당 발화를 기록하고 테스트 뒤
  올바른 내용을 짧게 알려준다.

## 5. 테스트 환경 준비

### 5.1 권장 환경

- 진행자가 로그인해 둔 태블릿 또는 노트북 1대
- 실제 서비스: <https://tpo-style-rescue-270725.panthea.chatgpt.site/>
- 관찰 기록지 1인당 1부
- 결과 판정표 1부
- 타이머 또는 시계

현재 사이트는 비공개이므로 진행자의 로그인된 기기를 사용한다. 참가자에게
ChatGPT 로그인이나 개인 계정 사용을 요구하지 않는다.

### 5.2 시작 전 점검

- [ ] 사이트가 시작 화면에서 정상적으로 열린다.
- [ ] 브라우저 확대가 100%다.
- [ ] 이전 참가자의 최고 점수는 판정에 사용하지 않는다.
- [ ] 아이템 카드 16개가 모두 표시된다.
- [ ] 우비·활동 바지·장화·투명 우산이 캐릭터에 정상 합성된다.
- [ ] 소리나 알림이 수업 공간을 방해하지 않는다.
- [ ] 참가자 기록지에 번호만 적혀 있다.
- [ ] 아이템 식별 카드와 실제 게임을 별도 탭으로 열어 두었다.

## 6. 진행자의 기본 원칙

- 참가자의 손과 시선을 먼저 보고, 말은 필요한 만큼만 한다.
- 10초 이상 멈춰도 바로 정답이나 누를 곳을 알려주지 않는다.
- “잘했어”, “그게 맞아”처럼 선택을 평가하지 않는다.
- “왜 그것을 골랐어?”처럼 이유를 묻되 답을 암시하지 않는다.
- 참가자가 한 말을 해석해 바꾸지 말고 가능한 그대로 기록한다.
- 진행자의 실수와 제품의 문제를 참가자의 실수로 기록하지 않는다.

### 6.1 도움 단계

참가자가 진행하지 못할 때 아래 순서로 한 단계씩만 제공한다.

| 단계 | 도움 | 기록 |
|---|---|---|
| H0 | 도움 없음 | 자립 완료 |
| H1 | 과업 문장만 다시 읽어 줌 | 가벼운 언어 지원 |
| H2 | 관련 화면 영역만 알려 줌 | 탐색 지원 |
| H3 | 조작을 한 번 보여 줌 | 자립 실패 |

어떤 단계의 도움을 제공했는지 기록지에 남긴다. H3를 사용하면 해당 과업은
도움 없는 완료로 계산하지 않는다.

## 7. 15분 진행 대본

### 7.1 도입과 참여 의사 확인 — 1분

진행자:

> “오늘은 네가 게임을 시험해 주는 사람이야. 너를 시험하는 게 아니라,
> 게임에서 헷갈리는 곳을 찾는 거야. 잘하고 못하는 답은 없어. 하기 싫거나
> 쉬고 싶으면 언제든 말해 줘. 시작해도 괜찮을까?”

아동이 동의하지 않거나 불편해하면 테스트를 시작하지 않는다.

### 7.2 과업 A: 글자 없이 아이템 구분 — 3분

`item-identification-cards.md`를 보여 준다. 한 번에 너무 많은 질문을 하지
말고 핵심 카드부터 묻는다.

진행자:

> “그림만 보고 무엇인지 말해 줄래?”

후속 질문:

- “언제 사용하면 좋을 것 같아?”
- “그렇게 생각한 그림의 부분은 어디야?”
- “비 오는 날에 도움이 될 것 같은 것은 어느 카드야?”

필수 확인 카드는 노란 우비, 장화, 투명 우산, 반사 밴드다. 시간이 남으면
16개 전체를 확인한다. “노란색이니까 우비지?”처럼 답을 넣어 묻지 않는다.

### 7.3 과업 B: 문자에서 TPO 찾기 — 2분

게임을 시작해 문자 상황까지만 진행한다. 옷장으로 넘어가기 전에 묻는다.

진행자:

> “이 문자를 보고 어떤 상황인지 네 말로 이야기해 줄래?”

필요한 경우 다음 질문을 각각 한 번만 사용한다.

- “언제야?”
- “어디에 가려고 해?”
- “무엇을 하려고 해?”
- “무엇을 조심해야 할까?”

때·장소·상황 중 자발적으로 말한 것과 질문 뒤 말한 것을 구분해 기록한다.

### 7.4 과업 C: 도움 없이 첫 코디 — 4분

진행자:

> “이 상황에 맞게 옷을 골라서 출발해 줘.”

이후에는 말하지 않고 다음 행동을 관찰한다.

- 첫 선택까지 걸린 시간
- 탭을 찾고 이동하는 방식
- 같은 부위 아이템을 교체할 수 있는지
- 캐릭터 변화에 시선이나 말로 반응하는지
- `모두 벗기` 또는 제출 버튼을 잘못 누르는지
- 타이머 때문에 조급해하거나 읽기를 포기하는지

진행이 10초 이상 멈추면 도움 단계를 적용한다.

### 7.5 과업 D: 선택 이유와 상황 변화 — 3분

결과 화면을 확인한 뒤 묻는다.

- “왜 이 상의와 신발을 골랐어?”
- “왜 이 소품을 골랐어?”
- “점수 말고 문자 속 상황으로 설명해 줄 수 있어?”
- “비가 그치고 밝은 낮이라면 무엇을 바꾸고 싶어?”
- “여기에서 덜 알맞았던 옷도 다른 때에는 좋은 옷일 수 있을까?”

방수, 미끄럼 방지, 활동성, 야간 가시성처럼 아이템 기능과 상황을 연결한
발화를 기록한다. 현재 에피소드의 오답을 언제나 나쁜 옷으로 일반화하는지도
확인한다.

### 7.6 과업 E: 재미와 재도전 — 2분

진행자:

- “가장 재미있었던 순간은 언제였어?”
- “가장 헷갈렸던 곳은 어디였어?”
- “다른 코디로 다시 해보고 싶어?”
- “다음 이야기가 있다면 해보고 싶어?”
- “이 게임의 재미를 1점부터 5점까지 고르면 몇 점이야?”

“재미있었지?”나 “다시 하고 싶지?”처럼 긍정 답변을 유도하지 않는다.

마무리:

> “게임을 고칠 수 있게 도와줘서 고마워. 네가 헷갈린 곳은 네 잘못이
> 아니라 게임이 더 잘 설명해야 하는 부분이야.”

## 9. 테스트 중단 조건

아래 상황에서는 즉시 멈추고 참가자를 보호한다.

- 아동이 그만하고 싶다고 말하거나 반복적으로 불편함을 보임
- 타이머나 점수 때문에 지나치게 불안해함
- 로그인·이름·연락처 등 개인정보 입력을 요구하는 화면이 나타남
- 안전에 관한 오해가 강화되거나 진행자가 바로잡아야 할 위험한 발화가 반복됨
- 사이트 오류로 정상적인 과업 수행이 불가능함

중단은 실패 참가자로 계산하지 않는다. 제품 오류라면 해당 과업의 분모에서
제외하고 결함으로 따로 기록한다.

## 10. 테스트 종료 후 순서

1. 참가자별 기록지에서 성공 수와 도움 단계를 확인한다.
2. 반복된 행동과 발화를 문제 단위로 묶는다.
3. `result-decision-sheet.md`에 인원수와 비율을 함께 집계한다.
4. 치명·주요 문제를 먼저 해결한다.
5. Revise이면 실패한 핵심 과업만 3명 이상에게 다시 확인한다.
6. Go 판정 후에만 에피소드 2와 스토리 확장을 시작한다.

Supabase와 실제 로그인은 이 테스트뿐 아니라 스토리 확장과 배틀 흐름 검증이
끝난 뒤 마지막 연계 단계로 유지한다.
