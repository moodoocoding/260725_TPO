## 5. 최종 판정

### Go

다음을 모두 만족하면 에피소드 2와 스토리 시스템 확장으로 진행한다.

- [ ] P0가 0건이다.
- [ ] 미해결 P1이 0건이다.
- [ ] 핵심 아이템 식별 목표를 충족한다.
- [ ] TPO 이유 설명 목표를 충족한다.
- [ ] 캐릭터 변화 인지 목표를 충족한다.
- [ ] 재도전·다음 이야기 의향이 75% 이상이다.
- [ ] 안전 관련 반복 오개념이 없다.

### Revise

다음 중 하나면 2~5일 수정 후 실패한 핵심 과업을 최소 3명에게 재검증한다.

- [ ] 특정 2~3개 아이템에 혼동이 집중된다.
- [ ] 목표 1~2개가 기준보다 10%포인트 이내로 부족하다.
- [ ] 선택 변화는 보이지만 교체·제출 조작이 불명확하다.
- [ ] P1 문제가 있으나 수정 범위가 첫 에피소드 안에 한정된다.

### No-go

다음 중 하나면 에피소드 확장을 멈추고 아트·학습·조작 가설을 다시 설계한다.

- [ ] 핵심 아이템 다수가 그림만으로 구분되지 않는다.
- [ ] 캐릭터 변화 인지율이 70% 미만이다.
- [ ] 그림이나 피드백이 안전 오개념을 반복적으로 만든다.
- [ ] 이미지 버전이 기존 CSS 버전보다 이해도와 재미를 개선하지 못한다.
- [ ] P0가 해결되지 않았다.

## 7. 다음 단계

- Go: 스토리 맵과 에피소드 2 콘텐츠 설계를 시작한다.
- Revise: P0·P1 및 실패 지표만 수정하고 짧게 재검증한다.
- No-go: 캐릭터·아이템 식별 또는 TPO 학습 구조를 다시 설계한다.

어떤 판정에서도 Supabase를 다음 단계로 당기지 않는다. 실제 로그인,
기기 간 동기화, 랭킹과 배틀 기록의 필요성이 검증된 뒤 가장 마지막에
연계한다.
