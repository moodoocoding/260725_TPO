## 1. 시뮬레이션 목적

실제 참여자 테스트 전에 다음 위험을 찾는다.

1. 처음 접한 성인이 어린이에게 게임 흐름을 설명할 수 있는가?
2. 교사가 점수와 TPO 학습 구조를 이해할 수 있는가?
3. 모바일 사용이 서툰 보호자가 다음 행동을 찾을 수 있는가?
4. 의상 선택과 캐릭터 변화라는 핵심 재미가 화면에서 보이는가?
5. 실수했을 때 쉽게 재도전할 수 있는가?

#### 0/4 조기 제출

- 의상을 하나도 고르지 않은 `0 / 4` 상태에서 `이 코디로 출발!` 버튼이 활성화돼 있었다.

- 결과는 8점, 별 0개였지만 상단에는 `MISSION COMPLETE`가 표시됐다.
- 시간 보너스만 8점을 받아 아무것도 선택하지 않아도 점수가 생겼다.

#### 실패 후 재도전

- 모바일 실패 결과 페이지 높이는 `2,534px`였다.
- `왜 이 코디가 구조 훈련에 맞을까요?` 영역은 약 `1,850px`에서 시작했다.
- `다시 코디하기` 버튼은 약 `2,300px`에 있었다.

- 모바일에서는 다음 행동, 캐릭터 변화, 실패 후 재도전이 모두 세로 스크롤에 묻힌다.

## 5. 발견 문제와 심각도

### SIM-S1-01 — 모바일에서 캐릭터와 의상 카드를 동시에 보기 어려움

- 심각도: `S1`
- 근거:
  - 캐릭터 이미지가 전환 직후 화면 기준 `-178~169px`
  - 의상 카드는 `418~870px`
  - 카드를 선택할 때 캐릭터 대부분이 화면 밖
- 영향:
  - 선택 즉시 캐릭터가 바뀌는 핵심 재미가 약해진다.
  - 상·하의 연결 상태를 바로 확인하기 어렵다.
- 권장 수정:
  - 모바일 옷장 상단에 축소된 캐릭터 미리보기를 고정한다.
  - 또는 캐릭터 영역을 접히는 고정 패널로 만들고 카드 스크롤과 분리한다.

### SIM-S1-02 — 0/4 상태에서도 코디 제출 가능

- 심각도: `S1`
- 근거:
  - `이 코디로 출발!` 버튼이 0/4에서 활성화
  - 실제 제출 시 8점 결과 화면으로 이동
- 영향:
  - 실수로 핵심 옷입히기 과정을 건너뛸 수 있다.
  - 아무것도 고르지 않았는데 시간 점수가 생겨 채점 의미가 흐려진다.
- 권장 수정:
  - 4/4 전에는 버튼을 비활성화한다.
  - 버튼 문구를 `4개를 모두 골라 주세요 (0/4)`처럼 진행 상태와 연결한다.
  - 키보드와 스크린 리더에서도 비활성 상태가 전달돼야 한다.

### SIM-S1-03 — 모바일 실패 후 재도전 버튼이 너무 멂

- 심각도: `S1`
- 근거:
  - 결과 페이지 높이 `2,534px`
  - 재도전 버튼 위치 약 `2,300px`
- 영향:
  - 실패 직후 회복 행동을 찾기 어렵다.
  - 낮은 점수 화면에서 이탈할 가능성이 높다.
- 권장 수정:
  - 실패 결과 상단 점수 바로 아래에 `다시 코디하기` 주 버튼을 배치한다.
  - 하단 버튼은 유지해도 되지만 상단 빠른 재도전을 제공한다.

### SIM-S2-01 — 모바일 시작 버튼이 첫 화면 아래에 숨음

- 심각도: `S2`, 실제 어린이가 반복적으로 멈추면 `S1`로 상향
- 근거:
  - 시작 버튼 상단 `1,092px`
  - 모바일 화면 높이 `844px`
- 영향:
  - 문자를 다 읽은 뒤 다음 행동을 찾지 못할 수 있다.
- 권장 수정:
  - 문자 카드 하단의 시작 버튼을 모바일 고정 하단 버튼으로 제공한다.
  - 또는 `문자를 읽고 아래 버튼을 눌러 주세요`와 스크롤 표시를 추가한다.

### SIM-S2-02 — 결과 화면의 핵심 학습이 아래쪽에 묻힘

- 심각도: `S2`
- 근거:
  - 데스크톱에서도 설명 영역이 약 `919px`부터 시작
  - 모바일에서는 약 `1,850px`부터 시작
- 영향:
  - 점수만 확인하고 TPO 이유 설명과 새 상황 문제를 놓칠 수 있다.
- 권장 수정:
  - 점수 바로 아래에 `왜 맞았을까요?` 요약과 새 상황 문제로 이동하는 버튼을 둔다.
  - 점수 상세표는 접을 수 있게 하거나 설명 뒤로 이동한다.

### SIM-S3-01 — 실패 결과에도 `MISSION COMPLETE` 표시

- 심각도: `S3`
- 근거:
  - 8점·별 0개 결과에도 `MISSION COMPLETE`
- 영향:
  - 실패인지 완료인지 메시지가 충돌한다.
- 권장 수정:
  - 60점 미만은 `MISSION RETRY` 또는 `다시 도전해 볼까요?`로 변경한다.

### SIM-S3-02 — 전환 후 스크롤 위치 유지

- 심각도: `S3`, 캐릭터 노출 문제와 결합될 때 `S2`
- 근거:
  - 문자 화면에서 스크롤 후 옷장으로 전환해도 `scrollY≈393px`
- 영향:
  - 새 화면의 시작 위치를 놓친다.
- 권장 수정:
  - 메시지→옷장, 옷장→결과 전환 때 적절한 기준 위치로 스크롤한다.
  - 단순히 항상 최상단으로 이동하기보다 모바일 고정 캐릭터 설계와 함께 검토한다.

## 6. 긍정적으로 확인된 항목

- 데스크톱과 모바일 모두 가로 넘침이 없다.
- 모바일 의상 카드는 2×2로 안정적으로 배치된다.
- 의상 4종의 이름과 기능 설명이 모두 노출된다.
- 90초 타이머, 카테고리 선택, 캐릭터 합성, 채점이 작동한다.
- 정답 조합은 높은 점수와 별 3개를 받는다.
- 점수 항목이 학습 목표별로 구분돼 있다.
- 예시 설명은 TPO 이유를 자연스러운 문장으로 연결한다.
- 새 상황 문제의 정답 피드백과 다음 임무 해제가 작동한다.
- 브라우저 오류·경고 로그가 없다.

## 7. 사전 Gate 판정

### 판정: 모바일 핵심 문제 보정 후 재시뮬레이션

데스크톱 기본 흐름과 학습 구조는 통과했다. 그러나 모바일에서는 옷을 고르는 동안 캐릭터 변화가 충분히 보이지 않고, 0/4 조기 제출과 긴 실패 회복 경로가 재현됐다.

따라서 다음 에피소드 확장보다 아래 세 항목을 먼저 수정하는 것이 좋다.

1. 모바일 고정 캐릭터 미리보기
2. 4/4 이전 제출 차단
3. 실패 결과 상단 빠른 재도전

그다음 순서로 시작 버튼 발견성과 결과 화면 학습 영역을 보정한다.

## 8. 권장 재시뮬레이션 기준

수정 후 다음 조건을 모두 확인한다.

1. 모바일에서 의상 카드 선택 중 캐릭터 얼굴과 착용 부위가 동시에 보인다.
2. 0~3개 선택 상태에서는 제출할 수 없다.
3. 4개 선택 시에만 제출 버튼이 활성화된다.
4. 실패 결과 첫 화면 안에 재도전 버튼이 보인다.
5. 문자 화면에서 별도 설명 없이 시작 행동을 찾을 수 있는 시각적 단서가 있다.
6. 점수 이후 TPO 설명과 새 상황 문제의 존재를 첫 화면에서 알 수 있다.
7. 데스크톱 기존 흐름과 채점 결과가 회귀하지 않는다.

## 9. 해석 제한

- 합성 페르소나는 실제 사용자의 망설임, 흥미, 읽기 능력, 터치 정확도를 측정할 수 없다.
- 실제 통과율과 만족도 수치로 사용하면 안 된다.
- 이 보고서는 고비용 사용자 테스트 전에 명백한 인터페이스 위험을 줄이기 위한 사전 자료다.
- 수정 후에도 최종 판단은 실제 어린이 3~5명의 관찰 결과로 내려야 한다.
